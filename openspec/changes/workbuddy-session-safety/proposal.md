# WorkBuddy 会话保护与当前渠道显示

## Why

官方 ACP authenticate 在新登录前先退出已有账号；WorkBuddy 的认证文件使用共享产品存储，实机在空 CODEBUDDY_CONFIG_DIR 中仍能读到同一账号，因此不能通过更换配置目录保证隔离。面板又会在登录开始时清空状态，失败后丢失原模型。标题栏缺少当前渠道和身份，用户无法识别实际连接。

## What Changes

- 已有账号的切换交给对应官方客户端，ChatSheet 不对该会话执行 authenticate。普通登录只在同一个 ACP 连接明确确认没有用户且模型探测明确未授权时继续；无法验证时仅重试。
- 跨宿主串行化登录；授权链接只在相应操作存活时允许重开。浏览器打开失败保留等待，取消、超时后废弃链接。
- 成功连接后记录非敏感来源标识，后续探测、对话和签到保持同一来源；失败不静默换账号。
- 短暂探测异常保留上次账号和模型并标记待验证；明确未授权才清除身份。登录操作失败保留原状态。
- 标题栏在导航图标前显示当前实际渠道和官方账号 ID；窄面板省略显示，悬停及读屏可读取完整信息。自定义 API/本机 CLI 不推测账号 ID。

## Capabilities

### New Capabilities

- `connection-identity`: 当前渠道与账号 ID 展示。

### Modified Capabilities

- `workbuddy-authorization`: 保护已有账号、固定来源、失败状态与授权链接生命周期。

## 确认

用户已在本任务确认前述方案及无法可靠隔离时交给官方客户端切换的后备方案，并要求显示当前渠道和可取得的账号 ID。

## Impact

修改 WorkBuddy 提供器、登录桥、设置与标题栏、定向测试；不读取认证文件、不复制令牌、不新增第三方服务。

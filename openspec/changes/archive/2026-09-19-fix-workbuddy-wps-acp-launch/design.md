# 设计

1. 统一用 `WorkBuddyProcess` 暴露 ACP 输入流、输出读取器、存活状态与释放操作。默认先走现有 `Process` 重定向路径。
2. 直接启动收到 Win32 “拒绝访问”时，创建两个仅本机、随机命名的 ACP 管道和一次性启动闸门，由 Windows WMI 进程服务在 WPS 宿主外启动隐藏的 `cmd.exe`。代理先阻塞在闸门，加入带 `KILL_ON_JOB_CLOSE` 的 Job Object 后才启动 CLI 并把 stdin/stdout 重定向到管道。WMI 调用和各管道连接分别记录阶段并设置超时。
3. 代理命令仅使用代码生成的固定参数和已分类的 CLI/配置目录；stderr 只排空，不写入面板或日志。正常取消会关闭输入管道，宿主退出或异常终止则由 Job Object 回收整棵代理进程树，不创建常驻服务。
4. 模型探测、账户授权和对话统一使用该传输，避免只修登录而模型仍不可用。
5. ChatSheet 安装脚本把最新官方版本文件以硬链接暴露在 `%LOCALAPPDATA%\ChatSheet\components`；链接删除不影响官方文件，硬链接不可用时才复制。运行时仍验证 PE 头。设置页下载 headless 安装器时同样通过 WMI 降级启动，并以版本目录出现作为成功条件。

## 安全边界

- 管道名使用不可预测 GUID，并限制为当前用户；不经网络监听。
- 不记录 ACP 原始消息、授权 URL 查询参数、令牌、密码或验证码。
- WMI 代理只在直接启动明确返回拒绝访问时启用；其他异常保持失败，不扩大执行面。

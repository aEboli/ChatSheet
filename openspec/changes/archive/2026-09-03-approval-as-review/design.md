# 设计：审批对照、跳转、诚实撤销、有范围的授权

实现前把几条容易写错的取舍钉死。规范写「做什么」，本文写「为什么不那样做」。

## 对照用探测已经读到的值，不再扫一遍

`DescribeImpactAsync` 已经为估算范围付过一次 `read_range`。对照的「原值」必须来自这一次，不要为了预览再读。审批发生在 UI 线程上，大范围第二次 COM 读取会让 Excel 假死，卡片却还没画完。

写公式时这一次探测改带 `include_formulas`。默认 `read_range` 只给 `Value2`，对照公式会把 `=A1+1` 显示成算出来的数字，批准的人以为在改值。

超限时探测失败，退回地址 +「读不到当前值」。不要为了对照去降采样——抽样预览看起来像完整表，比没有预览更糟。

## 预览上限取在面板能扫完、而不是单元格上限

5000 格整表进审批卡，窄栏（300–480px）会变成一张要滚动的电子表，批准按钮被顶出视野。截断规则：

- 最多 8 行 × 6 列画在卡上；
- 单元格文本最多 40 字，超长加省略号（加载项侧 `MaxCellTextLength` 是 512，给模型看的，不要用到卡上）；
- 实际范围更大时，表下写「还有 N 格未列出」，N 必须是剩下的格数，不是「还有几行」。

截断标记的字号和对比度走主题变量，浅色深色都要达到正文对比度。颜色不单独承担「这是截断」——色觉障碍下会看起来像完整表。

null 与空字符串要分得开：原值是空、新值是 `0`，和「读失败」不是一回事。空显示为「（空）」。

## 对照不进模型上下文

审批推送是给面板的。把预览矩阵写进工具结果或对话历史，等于每步批准再付一次 5000 格的税，而且 `TrimToBudget` 不压缩最近 6 条。预览字段只活在 `approval-request` 的 payload 里。

## Goto 不还原选区

`Application.Goto` 会改 `Selection`。曾经考虑高亮完把选区设回去，两条理由不做：

1. Office 对象不能比 COM 标识，保存再设回的 Range 是另一个代理，指错是静默的。
2. 系统提示的选区本就只在一轮开始时拍一次。用户批准期间自己点格子，和点卡片跳转，对模型来说是同一类过期。

悬停写「会把当前选区改到这里」。进行中的一轮里，「这里」可能已经不是发送时的选区——这是用户主动看的，不是加载项偷偷改的。

失败：工作表改名、地址失效，回传现有错误码（`SHEET_NOT_FOUND`、`RANGE_INVALID`），面板用现有错误呈现，不另选一张表。

## 图表名字从 Shape 上取，不是猜

`AddChart2` 返回 Shape。`Shape.Name` 是撤销时 `Shapes.Item(name)` 要用的那个。`Chart.Name` 在部分宿主上是图表对象名，不一定能当 `Shapes.Item` 的键。创建结果同时带 `chart_name`（Shape.Name）和可选的 `title`（用户给的标题，不是撤销键）。

没有名字就不登记 `Structure`。`CanUndo` 今天对任何非空 `Structure` 为真，所以「登记了但名字为空」必然做出注定失败的按钮。与其在 `DeleteChart` 里对 null 给出更长的错误，不如根本不登记——这正是 `sheet.fit` 已经写过的那句话。

图表恢复保持 `UNSUPPORTED`。`CanRedo` 对结构记录在撤销后为真（`Undone && Structure != null`），面板会把按钮改成「恢复」。必须在这条路径上让 `CanRedo` 为假，或面板在 `UNSUPPORTED` 的 redo 结果后撤掉按钮并写明原因。只修撤销、不修恢复，等于把谎言从「撤销」挪到「恢复」。

## 宿主用 0 表示「填充不统一」，不是黑色

实测记录（一格无填充、一格青色的范围，取范围级读数）：

| 属性 | 读数 |
| --- | --- |
| Bold / Italic / FontSize / FontColor | DBNull |
| InteriorPattern | DBNull |
| **InteriorColor** | **Double 0** |
| HorizontalAlignment / VerticalAlignment / WrapText | DBNull |

九项里八项如实返回 DBNull，只有 `Interior.Color` 返回 0。0 不是缺失值，
「跳过缺失值」的守卫拦不住它，于是还原真的把 Color 写成 0：**整片变黑**，
无填充那格的 Pattern 还从 xlNone 变成实心。已在 v0.7.1 上复现。

因此两处都要改，而且必须同步：

- **还原**：Pattern 与 Color 是一对，Pattern 读不出统一值时 Color 一并放弃。
  Pattern 有值（真的黑色填充时它是实心）才照原样写回。
- **判据**：`MissingCount` 对 Color 的计法必须与还原实际写不写它逐字一致，
  即 `IsMissing(Pattern) || IsMissing(Color)`。两处不一致的话，
  「能不能完整还原」这个问题会在卡片和撤销里得到不同答案。

副作用是「九项全缺」从不可达变成可达：八项 DBNull 加上被 Pattern 带走的 Color，
正好九项。此前那条「全缺就不登记」的规则是死代码，改完才真正生效。

## 混合格式：不登记，而不是登记一个什么都不还原的快照

`FormatSnapshot` 的注释已经说范围内不一致时宿主返回 null，还原时跳过，避免把参差抹平。跳过之后记录仍 `CanUndo`，按钮亮着，点了格子不动。用户以为格式已恢复。

适配对混合对齐的取舍是：逐格保得住才登记，否则不承诺。格式按**程度**分两档，
因为「不统一」在实测里几乎总是部分不统一：

- **全部九项都读不出统一值** → 这条记录什么也还原不了。格式是唯一维度时
  （`format_range`）放弃整条记录。
- **只有几项读不出** → 还原得回一部分。记录要留，但标 `FormatIncomplete`，
  卡片如实说「格式只能部分还原」。撤回大半比一点撤不了有用，
  但不能让用户以为撤干净了。

最初只做第一档，实测发现日常范围（加粗与字号各格不同、斜体换行对齐仍统一）
落在第二档，会被当成完整撤销。逐格外观矩阵本期**不做**——单元格数 × 每格九个属性，
COM 成本高于适配的两个对齐维度，也没有现成的 `allowCellwise` 开关。

`clear_range` 的内容维度仍登记：清除会丢值，值能逐格留底。只是格式维度在混合时缺席，撤销会把值找回来、格式保持清除后的状态。卡片必须说清「内容可撤销，格式不能完整还原」，不能只说「可撤销」。

## 重叠检测用地址区间，不比 COM 对象

两条记录同一张表、A1 地址的行列区间相交，即视为重叠。不要去拿 Range 对象做 `Application.Intersect`：每次解析都是新代理，而且撤销路径上工作簿可能已经变了。

并集地址（`B:B,D:D`）`RangeResolver` 目前交给 `Range`，Excel 会返回多区域，代码用 `Rows.Count × Columns.Count` 当尺寸，对并集是错的。本期不展开 `Areas`。重叠检测对解析后的单一 `Address` 生效；解析成一块的并集可能漏报，规范写明这条边界，而不是假装能处理多区域。

检测到重叠时**不要直接拒绝**。乱序撤销是 `UndoStore` 故意保留的能力（改 A 列与改 F 列不相干）。要拦的是静默覆盖。第一次点击返回警告（错误码独立，例如 `OVERLAP_WARNING`），卡片上出现「仍然撤销」；第二次才执行。不要用浏览器 `confirm()`——面板在 WebView2 里，系统对话框会把焦点从 Excel 抢走且对 UIA 不友好。

## 授权按「工作表 + 风险类」，不按「这张表」

ListObject 要先能被 `get_workbook_info` 列出来，模型才能稳定对准。本期没有那条读工具，绑定到表格名会变成「模型猜的名字」。工作表名来自探测后的 `ImpactEstimate.SheetName`，是宿主解析过的。

风险类分三档而不是按工具名逐个授权：清格式常常是 `format_range` + `set_number_format` + `fit_range` 交替，按工具名授权仍会弹三次。内容类（写入、清除、排序、合并）放在一起是因为它们都改值；用户允许「把这一列写成百分数」不该顺带允许「清掉整张表」，所以格式类与内容类必须拆开。

结构类永远单独问。`ApproveRest` 今天是一个布尔，执行器下一刀就不再询问，包括 `add_worksheet`。这是把「本轮全部允许」做窄的原因。

授权在 `RunAsync` 入口清空。`Automatic` 仍是开轮即 `_approveRestOfTurn = true` 的唯一路径；不要复用这个布尔来表达「格式类已授权」——结构调用会漏过去。用一个小的授权对象（sheet + class），结构不在里面。

关面板不清 runner（`EnsurePane` 见 `ComAddIn.cs`）。授权若写入 `Settings` 或磁盘，下一本工作簿会继承。只活在当前 `RunAsync` 的局部字段里。

## 空壳 PerTurn 不能留到「有空再修」

图标、设置项、README 三处都在描述一个执行器没有的模式。修文案把它改成「同逐项审批」更糟：用户已经按「每轮一次」在用那个盾。必须改执行器。

第一张卡仍然要出。那时还不知道工作表和类，预批等于全自动。所以「每轮确认」= 本轮第一次写入问一次，允许后记下 sheet+class，同类不再问。结构仍问。

## 主题与假 DOM

对照表、跳转按钮、授权芯片、重叠警告，一律走调色板变量，浅色深色一起做。漏适配不会报错，只会留白底。

面板单测的假 DOM 必须先变异一次再断言：对着空节点写「有一张 8×6 的表」会全绿。跳转是 `postMessage`，断言发出的 payload，不要在测试里复刻 Goto。

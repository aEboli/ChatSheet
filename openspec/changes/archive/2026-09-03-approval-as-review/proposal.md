# 提案：让「允许」成为核对

## 问题

默认处理方式是逐项审批。用户每天要点十几次「允许」，卡片上却只有三样东西：工具名、风险、影响范围（「Sheet1 的 2-10 行 × B-D 列，共 27 个单元格」）。`summarizeArgs` 对数组只输出形状：`values: 20 行 × 3 列`。将写入什么、原来是什么，批准前都看不见。

这不是漏了一句文案。加载项为了估算范围，已经付过一次最多 5000 格的 `read_range`（`AgentRunner.DescribeImpactAsync`），然后把值扔掉，只把表名、地址、格数交给面板。架构文档把「diff 预览」写成选 WebView2 的理由之一，这条路径付了 COM 成本，预览却没出现。

另外三件事让「允许」更像仪式：

**地址是死文字。** 卡片已经把位置写出来了，桥通道却只有 `sheet.fit`。核对要自己去 Excel 里翻。`workbook.summary` / `workbook.selection` 是只读的，面板根本没在用。

**撤销会说谎。** `sheet.fit` 已经立过规矩：做不到的按钮不要放。模型路径没守。

- `create_chart` 的返回没有 `chart_name`。撤销登记仍会放一条 `Structure` 记录（`CanUndo` 只看 `Before != null || Structure != null`），点下去 `DeleteChart(sheet, null)`，得到 `找不到图表「」`。注释自己写了「留空并在撤销时给出明确提示」，按钮却照常亮着。图表的恢复本来就是 `UNSUPPORTED`，撤销成功后按钮变成「恢复」，再点一次又失败。
- 范围内格式不一致时，宿主对范围级属性返回 null，`FormatSnapshot` 如实记下。还原时跳过 null——操作标「已撤销」，格子不动。适配对混合对齐已经选择「不登记」，格式/清除没有走同一条路。
- 两条写入范围重叠时，撤较早那张会静默盖住较晚那张。`UndoStore` 的类注释承认了这个代价，界面上没有任何警告。尺寸变了会报 `SHAPE_CHANGED`，内容被后一次写入覆盖了不会。

**「每轮确认」是空壳。** 设置和图标（半填充盾）都说每轮开头确认一次。`AgentRunner` 只在 `Automatic` 时预批准，选 `PerTurn` 与 `PerWrite` 执行路径相同。README 自己标了实验性，设置页没有。唯一的一键出路是「本轮全部允许」，它是一个布尔，格式和「新建工作表」一起放行。日常清表是十几张几乎一样的格式卡，用户要么点十几次，要么放弃全部审批。

v0.5–v0.7.1 把「哪个模型能用」和「点了有没有反应」做完了。表格工具面从 merge/fit 之后没动过。下一刀不该再加动词，该让已经存在的审批真正看见它在批什么。

## 改动

### 1. 审批卡给出截断的前后对照

`ImpactEstimate` 不再在探测之后丢值。写值、写公式把探测到的原值与参数里的新值按格对齐，送给面板一份**截断预览**（上限见设计）：每格原值 / 新值，外加「还有 N 格」。截断必须看得出是截断，不能看起来像整张表。

写公式的探测带上 `include_formulas`，对照的是公式文本，不是算出来的值。

格式、数字格式、适配：卡片继续展示将应用的参数；范围级属性为 null 时加一句「当前格式不统一」，不为此再倒一份格式矩阵进面板。

`fit_range` 省略 `range` 时，审批前先解析成 UsedRange 地址再探测，不能再交出一张影响范围空白的卡。探测失败（超限、无效地址）仍出卡，写明「读不到当前值」，不要用空表假装读过。

预览只给用户看，不进对话历史、不回传模型。

### 2. 范围可以点进 Excel

新增 UI 线程通道 `sheet.goto { sheet, address }`：激活工作表并对该范围 `Application.Goto`。解析失败按现有 `ToolException` 回面板，不静默改选别处。

审批卡的影响范围、操作卡成功摘要里的位置、轮次组展开后的地址，凡是已经译成「行号 × 列字母」的，都是这个动作的入口。入口要能当按钮用，不能只靠颜色。

Goto 会改变用户当前选区——系统提示本来就只在一轮开始时拍一次选区，用户自己点格子也一样。悬停说明写清这一点，不在 COM 里尝试「高亮完还原选区」：Office 对象不能比标识，还原选区很容易指错。

### 3. 做不到的撤销不给按钮

三条，都不新增产品表面：

- `create_chart` 回报 Excel 赋给 Shape/Chart 的 Name。登记撤销时没有名字就不放 `Structure`（或 `CanUndo` 为假），并说明原因。恢复图表仍然做不到：撤销之后按钮不得变成「恢复」，否则第二次点击注定失败。
- 格式快照在范围级属性全为 null、又没有一份完整的逐格外观时，不登记格式撤销——与适配对混合对齐的取舍同一句话：保不住足以完整还原的快照，就不承诺可以撤销。
- 撤销前扫描尚未撤销、且工作表与地址相交的较新记录。有重叠则这次调用返回可确认的警告，而不是直接覆盖；按钮的悬停写明「与之后的写入重叠」。多区域地址本期仍按 `RangeResolver` 现有行为（并集只解析成一块），不在本期展开 `Areas`。

60 条上限不变。被挤掉的记录对应卡片若还在，撤销入口去掉并说明「记录已超出保留范围」。

### 4. 「每轮确认」变成有范围的授权

执行器区分三种策略，设置文案与盾牌第一次和实际行为一致：

| 策略 | 行为 |
| --- | --- |
| 逐项审批 | 每次写入都问。卡片上「本轮同类允许」只放行**同一工作表、同一风险类** |
| 每轮确认 | 本轮第一次写入问一次；允许之后，同一工作表、同一风险类自动放行 |
| 全自动 | 不问。这是唯一真正放手的档 |

风险类：

- **格式类**：`format_range`、`set_number_format`、`autofit_range`、`fit_range`
- **内容类**：`write_values`、`write_formulas`、`clear_range`、`sort_range`、`merge_cells`、`unmerge_cells`
- **结构类**：`add_worksheet`、`rename_worksheet`、`create_table`、`create_chart`

结构类**不**被格式/内容授权覆盖。要放行结构，必须点一个写明「含结构」的按钮，不得沿用今天「本轮全部允许」那个不加限定的布尔。

当前授权显示为盾牌旁的一枚芯片（工作表 + 类），盾牌不再在「每轮确认」下假装少问。授权只活在本轮、本面板；关面板不清 runner，所以授权不得做成跨会话、跨工作簿的。

「绑定到这张表（ListObject）」本期不做：`get_workbook_info` 还不列表格。工作表 + 类够覆盖「清这张表的格式」那十二张重复卡。

## 影响范围

加载项：`ImpactEstimate`、`DescribeImpactAsync`、`create_chart` 返回值、`BuildStructureAction` / `CanUndo`、`Undo` 的重叠检查、`ApprovalPolicy` 的实际分流、`AgentChannels` 增加 `sheet.goto` 并扩展审批推送。

面板：`addApprovalCard` / `summarizeArgs`、范围标签可点、授权芯片、「本轮同类允许」与「含结构」的文案、两套主题下的对照表与芯片。

规格：`panel-operation-cards` 增补审批对照、跳转、撤销诚实；新增 `approval-policy` 把处理方式从空壳变成可验证行为。

验证：工具层补建图撤销、混合格式不登记、重叠警告；面板单测补对照表渲染与跳转请求；假 DOM 必须先变异一次再断言。`verify-chat-e2e.ps1 -Approval PerWrite` 至少覆盖「对照出现在批准之前」。

## 不在本期

- `read_profile` / 写入短回执、插入删除行列、边框、查找替换、删除工作表。
- 会话按工作簿拆分、变更清单导出、审计 JSONL。
- 授权登录、WPS、把 xlsx 当附件。
- 让「每轮确认」在第一张卡出现之前就预批——那时还不知道工作表和风险类，预批等于全自动。

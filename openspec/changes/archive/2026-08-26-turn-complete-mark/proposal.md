# 提案：一轮正常收尾时留一条「已完成」

## 问题

**一轮怎么结束的，只有出问题时才说。** 加载项有五条终止路径，其中四条各留一条居中
胶囊：被停止（「已停止生成」）、达步数上限、反复截断后放弃、出错。第五条——正常
跑完——什么都不留。

于是屏幕上这两种情况长得一模一样：

```text
助手：我已经把 B 列改成日期格式了。          ← 真的做完了
助手：我先读一下 B 列的现有格式，然后……      ← 被停止/截断，最后一段话看着像结论
```

第二种尤其难辨：模型被截断时最后那半句往往正好读起来像个交代。用户要确认「这轮到底
完没完」，只能去翻 `%LOCALAPPDATA%\ChatSheet\logs`——而那行日志本身也不可信（
`AgentRunner` 里「对话结束」是正常收尾才打的，但停止与截断走的是别的分支，日志上
的表现各不相同）。

换句话说：**四条异常路径都在说话，唯独「正常」是沉默的，而沉默无法与「没说出口的
异常」区分。**

## 改动

正常收尾时在对话流中间插一条「已完成」，位置与错误、停止那几条完全相同——都是
居中胶囊：

```text
你：把 B 列改成日期格式
助手：改好了。
▸ 第 1 轮 3 个操作（1 改，2 读）              [还原]
                    已完成                            ← 这一条
```

用主色那一套（`--accent-bg` / `--accent-border` / `--accent-text`），与琥珀的警示、
红的错误并列成第三档。描边取 `accent-border` 而不是满饱和度的 `accent`：正常收尾是
最常出现的一条，描边和文字都用主色会比错误还抢眼。

**只在 `turn-complete` 时插。** 加载项那五条路径互斥——`stalled`、`step-limit`、
`stopped`、`error` 各自 `return` 而不再发 `turn-complete`——因此不会出现「已停止」
紧跟着「已完成」这种自相矛盾的收尾。这一点是本次改动的要害：冒出一条矛盾的收尾
比什么都不显示更糟，用户不知道该信哪个。

**这条标记的用处主要在它不出现的时候。** 有它就是正常收完；没有它，那一轮就是中途
断了——而断的原因由旁边那条对应的胶囊说明。悬停说明把这层意思写出来：
「这一轮已正常结束。没有这一条就说明中途断了（被停止、达上限或出错）」。

**它是每轮的最后一行。** 轮次操作组在下一轮开始时形成，本来会追加到它后面，那样
读下来是「回复 → 已完成 → 一组操作」，收尾之后又冒出内容。成组时把这条标记重新挂
到末尾（同时刷新挂载序号，好让还原时按序号重排的结果与此刻一致）。

被停止那一轮不做这件事：它没有完成标记，组落在停止说明之后即可。只特判完成标记
一种，是因为它有专门的类名；错误胶囊则可能出现在一轮中间（工具失败、审批失败都会
插），分不出哪条是终止的那条。

## 影响范围

面板侧只碰 `chat.js`（`markTurnComplete`、成组时把标记移回末尾、布局自检加计数）
与 `app.css`（一条 `.notice-ok` 变体）。加载项侧不动：`ReadLastNotice` 按 `.notice`
取，这条标记自然被它看见。

修订规格 `panel-operation-cards`，新增一条要求。不动的东西：五条终止路径本身、
各自那条胶囊的文案、操作卡片与轮次组的结构。

# 提案：排队条限高三条并可滑动，取消即消失

## 问题

一、**排队条会无限往上长。** 现在有几条排队项就画几条，`.queue-strip` 只设了
`overflow: hidden` 兜横向。排到五六条时这一条会把对话区往上顶掉近一百像素——
而面板本来就窄，被挤掉的正是用户在读的回复。排队条的用处是「还有什么在排」的索引，
不是把整个待办清单摊开。

二、**取消掉的输入仍占着对话流。** 取消后那条会以划掉的气泡落进对话流末尾，
标注「已取消，未发送」。当初这么做是想留住用户写过的字，但代价是：一条根本没发生过
的输入被永久记进「已经发生的事」里，取消几次对话流就积几条噪声，而它们既不能重发，
也不参与上下文。用户的判断很直接——已取消就不该出现在对话框里。

## 改动

**排队条限高到三条。** 高度上限按三条排队项加两道间隙算（`3 × 18px + 2 × 3px`），
写成派生自条目高度与间隙的 CSS 变量，改样式时两处不会各算一遍。超出后竖向可滑动，
横向仍然裁掉（横向溢出会顶出整页滚动条，app.js 的布局自检把它算作缺陷）。
滚动条收窄到 6px，免得在窄栏里吃掉正文的横向余量。

**滑动的初始位置对着队首。** 排队条是 `column-reverse`，队首在最下面。整条重画
（`replaceChildren`）会把滚动位置清掉，于是每次重画后显式把视口拉回队首那一端：
用户最关心的永远是「下一个发哪条」，早排的往上滑才看。

**取消即消失。** 取消一条、停止时清空队列，都只是把它从队列里去掉并重画排队条，
不再往对话流里插划掉的气泡。停止时仍然告知取消了几条——那是对「停止」这个动作的
回执，一行系统提示，不是把内容再摊一遍。

代价说清楚：**取消掉的那段文字不再有地方可取。** 排队项上只有截断的一行，完整正文
在悬停说明里，取消后二者一并消失。用户按下取消时的意思是「这条不要了」，本次按这个
理解做；若之后发现确实需要留一份，那是另一个改动（比如取消时把原文回填到空的输入框）。

## 影响范围

改动集中在面板的 `app.css`（排队条限高与滚动条）与 `chat.js`（重画后归位、
取消不再上屏），加上不再产生 `.msg-cancelled` 后的清理：那三条 CSS 规则、
`TaskPaneControl.ReadQueueState` 里的「已取消」两个字段、以及 `verify-chat-queue.ps1`
中据此断言的一条。修订规格 `chat-input-queue` 里「排队内容显示在哪、取消后怎么留痕」
这两条要求。队列语义没动：仍是 FIFO、单实例轮转、附件入队时取快照、停止与新会话清空。

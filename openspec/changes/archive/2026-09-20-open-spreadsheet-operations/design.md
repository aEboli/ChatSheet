# 审计与设计

## 最终实现调整

用户确认并要求工具调用也开放后，采用原有专用工具加一个通用 excel_object 的方案，避免为每个 COM 成员重复注册入口。get_workbook_info 返回宿主版本和操作类别；成员的具体兼容性以执行与读回为准。此实现不采用任意 shell/VBA。

长文本在 Excel 单格上限内完整返回，替代分段文本游标；大范围读取仍按 5000 格分页，写入按相同块大小执行，失败返回实际完成格数。专用矩阵工具继续要求连续范围，多区域格式等通过通用入口执行宿主语义。无进展保护明确为连续八次同工具、同参数、同错误；不按固定步数截断正常分页任务。

以下是原审计和设计依据；以此段、最终增量规范及 validation.md 中的实测结果为最终交付边界，不能将能力矩阵理解为所有宿主成员已经逐项测试。

## 执行原则

1. 复用现有 Automatic 分支，不删除 RequiresApproval 风险元数据，因为结果卡片和撤销说明也依赖它。默认变化不会强制覆盖其他用户已保存的审批选择；本次安装按用户请求明确切换。
2. 不把所有限制常量改成 int.MaxValue。读取全工作表有 17179869184 个格，整片物化无法可靠执行。读取返回有界页面、完整范围元数据、下一页游标及截断标记；模型可以继续读取全部所需数据。超长单元格提供分段读取，避免 512 字符截断导致永远看不到后半段。
3. 格式、清空、排序、建表与建图尽量直接调用宿主范围方法，不为执行而将整个范围复制到模型上下文。排序保持全范围排序，合并保持原合并语义。写入分块并记录已完成位置，失败报告部分结果。
4. 非连续区域逐项预检；矩阵写入要求逐区域数据映射。排序、合并或建表遇到宿主不支持的并集，解释无法执行的具体语义，不改成其他目标。
5. 缺失能力采用明确的结构化工具族，沿用当前工作簿对象、UI 线程调用和 COM 释放方式。实现时先查官方对象模型/源码，逐项确认成员和兼容性，不依赖任意 shell 或 VBA 作为万能通道。
6. 所有执行返回真实成功、失败或部分完成；可撤销性独立报告。涉及结构变化的撤销必须有可验证实现，否则不显示可撤销。
7. 保留指向正确工作簿、停止后不写入、合法参数和宿主原生保护检查。这些保证操作对象和结果正确；密码保护只允许在用户提供有效密码时按宿主接口处理，不伪装已解锁。

## 能力验收矩阵

| 工具族 | 最低验收范围 |
| --- | --- |
| 范围与数据 | 分页读值/公式/长文本、分块写值/公式、清空、查找替换、复制/移动/选择性粘贴、填充序列 |
| 行列与工作表 | 插入/删除行列、隐藏显示、尺寸设置、复制/移动/删除工作表；原有新增重命名回归 |
| 格式 | 字体、填充、边框、数字格式、缩进、方向、完整常用对齐、合并取消合并 |
| 数据规则 | 筛选/清除筛选、多键排序、去重、命名区域、数据验证、条件格式 |
| 表格对象 | 创建/调整/删除表格、表格样式、汇总行、结构化引用 |
| 图表与透视 | 图表查询/更新/删除、系列和布局；透视表创建/字段配置/刷新/删除 |
| 视图与打印布局 | 冻结/取消冻结、显示隐藏、页面设置、打印区域；不默认触发实体打印 |
| 宿主兼容 | 能力查询反映实际 Excel/WPS 支持，不支持的功能有可操作错误说明 |

“全部可行”以宿主当前工作簿对象模型支持且已实现、已验证的操作为准，不能把有限工具清单描述为覆盖 Excel 的全部功能。新增操作必须在矩阵中登记，无法实现的宿主能力如实列出。

## 验证

- 定向回归：5001 格、整列格式、跨 40 步有进展任务、多区域、审批全自动、新增工具协议和部分失败。
- 临时 Excel 工作簿实测每个工具族，对实际值、公式、格式、对象及结构读回断言；同时验证停止、切换工作簿和撤销不回退到错误对象。
- 使用独立 WPS 临时工作簿复测可用工具族，登记不兼容项。
- Release 构建、相关 C# 和 Web 回归、OpenSpec 严格校验；中文文件检查 UTF-8 与异常替换字符。
- 构建并验证之后再更新本地安装，宿主占用 DLL 时先请求保存关闭，不能直接结束用户宿主进程。

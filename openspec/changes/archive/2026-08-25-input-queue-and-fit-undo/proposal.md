# 提案：输入排队、适配撤销修复与英文思考档位

## 三个问题

**一、面板「适配」不能撤销也不能恢复。** 点适配后提示上出现撤销按钮，点下去报
「找不到该操作记录，可能已超出保留范围」。日志显示同一个撤销栈里模型调用留下的
记录能正常撤销，只有适配那两条找不到——它们从未登记过，而面板却拿到了标识。

成因有两处，各自看都合理，凑在一起就成了「按钮在，但注定失败」：

1. `fit_range` 允许省略 `range` 由工具自取已用范围（面板按钮正是这么调的），
   而撤销快照必须在操作前采集。执行器直接拿参数里的 `range` 去采，拿不到地址，
   快照放弃，记录没登记。
2. `sheet.fit` 通道无条件回传撤销标识，不问是否真的登记成了记录。

现场还叠了一层：Excel 加载的是安装目录里的 DLL，当时装的是更早的构建。

**二、任务进行中不能输入。** 处理中输入框被禁用，想到的下一步只能干等或记在别处。
加载项同一时刻只跑一轮这个限制本身是必要的——两轮交替写同一个工作簿会互相踩踏——
但把它表达成「禁用输入框」把成本全压给了用户。

**三、思考档位显示中文。** 「低」「超高」「最大」。可档位名同时是排查时要在日志、
请求体和官方文档之间对照的东西，多一层翻译就多一次心算：「超高」对应 `xhigh`
还是 `max`，字面上看不出来。

## 改动

### 适配撤销（不新增能力，修复既有行为）

- 执行前把隐式范围解析回参数，让快照有地址可采；解析失败仍走原路径转成结构化错误，
  不改变错误契约。
- 只有确实登记成记录才回传撤销标识。宁可不给按钮，也不给注定失败的按钮。
- 没有撤销入口时把原因并进同一条提示：缺按钮是可见的，缺原因会被当成故障。

### 输入排队（新增能力，见 `specs/chat-input-queue`）

输入框不再禁用；处理中提交的内容进队列，上一轮结束后自动接着跑。队列放在面板侧
而不是加载项：排队条目要能看见、能取消，这两件都是界面的事，后端多一个队列反而要
再开查询与撤单两条通道。代价是刷新面板会丢掉未发出的排队项，与丢掉输入框草稿同级。

发送按钮由两态改为三态。有输入时让「加入队列」压过「停止」：输入框里有字说明用户
正打算安排下一步，此时点按钮几乎不可能是想中断；而要停止只需清空输入框，代价很小，
反过来把排队藏起来则没有同样便宜的替代入口。

停止连带清空队列——否则停完当前一轮又自动开跑下一条，等于没停。

### 英文思考档位（文案）

`Off / Minimal / Low / Medium / High / XHigh / Max`，与三家协议的参数取值逐字一致。
说明文字仍用中文：那是解释用途，不是标识符。

## 影响范围

新增规格 `chat-input-queue`。改动集中在面板脚本、`sheet.fit` 通道、执行器的快照
预处理与 `Thinking.Options`；新增五个自动化测试钩子以便端到端验证排队与适配撤销。
不涉及工具目录、协议映射与权限边界，不新增网络或文件系统能力。

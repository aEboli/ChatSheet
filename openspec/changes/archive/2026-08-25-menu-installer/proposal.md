# 提案：双击式安装器，输入编号选择

## 问题

安装的唯一入口是一行命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Action install
```

这行命令对不用命令行的人有三处门槛：得知道怎么在解压目录里打开 PowerShell、
得原样敲对包括 `-ExecutionPolicy Bypass` 在内的全部参数、还得知道换成 `uninstall`
或 `diagnose` 才能做另外两件事。而 `.ps1` 双击打不开——Windows 会用编辑器打开它，
默认执行策略也会拦下来。

结果是这个项目明明只有三个操作，却没有一个不用记命令的入口。

## 改动

根目录加一个双击就能跑的 `install.bat`，打开菜单输入编号：

```text
  当前状态：已安装 0.2.1.0（2026-08-25 18:26）
  运行模式：源码检出（安装前会先构建，需要 .NET SDK）
  安装位置：C:\Users\Administrator\AppData\Local\ChatSheet\app

  [1] 安装或更新    覆盖安装并注册，Excel 需重启才生效
  [2] 卸载          反注册并删除安装目录，保留日志与设置
  [3] 诊断          检查运行时、COM 注册、宿主登记与日志
  [4] 退出
```

菜单先报三件事再给选项：装的是哪个版本、当前是源码检出还是预构建发行包
（决定「安装」会不会先 `dotnet build`）、装到哪里去。这三件事是任何人打开安装器
最先要知道的，也是判断「我这次点 1 会发生什么」的依据。

`install.ps1` 一行没改，仍是真正干活的脚本；菜单只负责问清楚做哪件事。
根目录到 `scripts/` 的相对位置在源码检出和发行包里是一样的，所以同一个 `.bat`
两种布局都能用，不必为发行包单独做一份。

## 三个不那么显然的约束

**提权必须在菜单启动时做，不能留给每个动作。** `install.ps1` 未提权时会经 UAC
重启自身，跑完后 `exit` 整个进程——菜单会跟着一起消失，用户点一次就没了。
菜单启动时提一次，之后每个动作都在同一个窗口里跑完，既不再弹 UAC，也不会跑完就没。
代价是只想诊断的人也要授权一次；为此把菜单拆成两种权限只会多一次弹窗和一次解释。

**动作要用 `&` 调用，不能点源。** `exit` 在被 `&` 调用的脚本里只结束它自己，
点源会把菜单一起带走——与上面同一个坑的另一面。

**`.bat` 里一个非 ASCII 字符都不能有。** 控制台按 OEM 代码页（中文 Windows 上是 936）
读批处理文件，中文写在里面会变成乱码，甚至让解析器出错。因此 `.bat` 只做转发，
所有中文都在 `menu.ps1` 里——而它必须是带 BOM 的 UTF-8，否则 PowerShell 5.1
会按 ANSI 读，中文同样成乱码。这是仓库里其他 `.ps1` 已有的约定。

## 影响范围

新增根目录 `install.bat` 与 `scripts/menu.ps1`。`package-release.ps1` 把两者纳入
发行包并加进必需文件校验。README 与 `docs/windows-release-install.md`
（发行包内的 `INSTALL.md`）改为以双击入口为主、命令行为备。

修订规格 `windows-release-distribution`，新增「双击入口与编号选择」一条要求。
安装、卸载、诊断本身的行为一个字没改。

# 提案：合并单元格工具

## 问题

用户要求合并单元格，模型回答自己做不到，并列出了能做的事（读写值和公式、字体、
填充、对齐、数字格式、排序、建表格图表），说唯独没有合并功能。

这个回答本身没有说错，它准确复述了工具清单——清单里确实没有合并。错的是清单：
合并单元格是 Excel 排版最常用的操作之一，做标题行几乎绕不开。功能区上它是一个
按钮，而 ChatSheet 让模型「通过受限的表格工具完成任务」，这个受限集合漏了它。

漏掉不是因为难，而是因为它是所有写操作里唯一会静默丢数据的一个：宿主只保留
左上角单元格的值，其余一概丢弃，事后没有任何迹象可查。这一点决定了它该怎么加，
而不该不加。

## 改动

新增两个工具，风险级别都是 `Write`（默认逐项审批）：

- `merge_cells`：把范围合并成一格。`across` 为真时逐行分别合并。可顺带设置水平
  与垂直对齐，因为功能区上「合并后居中」是一个按钮，用户说「合并」时想要的往往
  就是那个效果；分成两次调用会留下两条撤销记录，用户点一次却要撤两次。默认不改
  对齐——已经排好版的表不该因为合并一个标题就被重新对齐。
- `unmerge_cells`：把范围内相交的合并区域拆回独立单元格。

围绕「会丢值」这一点做三件事：

**合并前先数清楚要丢什么。** 工具在动手前整片读一次值，把将被丢弃的非空单元格
个数回报给模型（`discarded_values`）。这是模型判断「该不该先问用户」的唯一依据。
工具说明也写明合并前应先读一遍范围。

**撤销要把值找回来，而不只是把格子拆开。** 合并的撤销快照按单元格记内容，
因此受 5,000 单元格上限约束——超限时拒绝执行并要求分批，而不是做一个撤不回来的
丢值操作。取消合并不丢数据（原内容留在左上角），只需记下原有的合并区域。

**不弹宿主的确认框。** 合并含多值的范围时 Excel 会弹「仅保留左上角的值」。
加载项跑在宿主 UI 线程上，弹框会把 Excel 连同面板一起冻住，且没有人能点它——
用户的许可已经由面板的审批卡收过一次。执行期间关掉 `DisplayAlerts` 并在之后还原。

系统提示的「能力边界」一行同步加上合并与取消合并。模型答「我做不到」的直接依据是
工具清单，但那一行也在反复告诉它自己只能做哪几类事。

## 影响范围

新增 `Tools/ToolExecutor.Merge.cs`；`ToolCatalog`、`ToolLimits`、`ToolExecutor.Read.cs`
的分派与撤销描述、`UndoStore.DetailFor`、`UndoTypes`、`SnapshotCapture` 各有增补；
`SystemPrompt` 能力边界一行；面板 `chat.js` 的工具名中文标签。

新增规格 `cell-merge-tools`。既有工具的行为、上限和撤销语义都没有改动。

# model-availability

网关常返回几十上百个模型 ID，其中多数用不了，而 `GET /models` 只给名字。这个变更
让用户不必靠反复试错来记住哪几个能用。

- **判定从真实对话里白拿**：一轮到达了模型即记「可用」，一轮失败且服务端错误点名
  了该模型即记「不可用」，其余一律「未知」。不额外发任何请求——这份信息用户已经
  付过钱了。
- **常用的排在最前面**：名单里的模型排在目录之前，无条件生效，不需要任何开关。
  上百个 ID 的问题当场变成「前几个里挑」。
- **一个开关收窄列表**：默认关。开启后只显示名单里的模型；名单里没有一个出现在
  当前目录时自动显示完整目录——开关不会把人锁在外面。
- **标注只加不减**：判定永远不从选择器里移除任何东西，隐藏只由用户的开关决定。
  所以误判的代价上限是「标错一次」，而不是「一个好模型被永久藏起来」。

「可用」在这里只指「一次请求到达了模型并得到回复」。不支持工具调用的模型是可用的
——既有规范已经为它准备了顾问模式。

按需「试一下」留到二期：审计发现那条最小请求通路与真实对话的形状不一致，会两头
误判。待修前提与结论记在 `design.md`。

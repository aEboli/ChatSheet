# 2026-08-30：判定一眼看得见，思考等级一行一档

不可用的模型名变红；思考等级改成一行一档、占满整段宽度；每档的用途说明与
行内的「试一下」都收进悬停。

## 问题

### 结论画得太小，等于没画

判定落在模型名之前一个 7px 的点上。点会变色，但紧挨着它的模型名始终同一个黑——
一列几十行扫下去，「能用」与「报错说没这个模型」逐字同色。

行上确实还有一句 10px 的结论小字，但它让每一行都变成两行。于是这句字既没让结论
变明显，又把列表密度砍掉一半——而这一列要装的是几十个模型。

### 档位列窄到装不下自己

浮层左右分栏、模型段 62% 档位段 38%，浮层下限 260px。去掉边框内边距后档位段只有
一百出头：`Minimal` 加一句「当前模型会降级」必然折行，每档十几个字的说明摊在行上
就是七行小字。

### 几十行几十个按钮

「试一下」只对没有判定的模型显示——而没有判定的往往就是大多数，这个入口本来就是
为「从没用过的模型」造的。于是常见情形是一列按钮墙，而它是偶尔才用一次的动作。

## 改动

### 判定落在模型名上

| 三态 | 模型名 | 点 |
| --- | --- | --- |
| 可用 | 常规字色 | 实心绿 |
| 不可用 | **红** | 实心红 |
| 未确认 | 常规字色 | 空心描边 |
| 正在确认 | 弱化色 | 琥珀描边并闪动 |

**可用刻意不上绿。** `--accent` 已经是当前选中项的颜色，两处都用绿会分不清
「这个能用」与「现在用的是这个」。用户问这份列表的问题是「哪几个不能用」，
那才是值得做到不可能看漏的那一条。

摘要行的不可用也从琥珀改成红：同一件事在摘要行与列表里换个颜色，用户要学两遍。
琥珀在这个控件里已经归「会降级」用了。

三态的结论文字随之收进悬停说明。**「正在确认」仍留在行上**——那一态没有颜色可依，
而它是「慢网关」与「点了没反应」的唯一分辨依据。

### 浮层左右分两列，宽度按内容定

左列模型、右列档位。两边的宽度都交给浏览器量：档位列 `width: max-content`
（正好容下 `Minimal` + 「会降级」标注，实测行宽 93px），浮层整体也是 `max-content`
并以面板宽度为上限。

浮层宽度经过三轮：`min-width: 300px`（会一直顶到 max-width，几乎占满整行）
→ 定值 296/320px（ID 短时右边空一块，ID 长时被截断）→ `max-content`
（短目录窄、长 ID 宽，两头都不浪费）。

档位列一开始还多占了六十来像素：列头挂着一句「悬停看说明」，而这一列按 max-content
定宽，那句小字比最长的档位名还宽，于是它一个人把整列撑宽，右侧一片空白——挤掉的正是
模型 ID 的横向空间。去掉那句后行宽从 104px 降到 93px。

档位名居中而不靠左：这一列只有档位名那么宽，靠左时右侧余下的空白会让整列读成
「贴着分隔线的一竖条」。`space-between` 更不行——只有一个子元素时它等于靠左，
有标注时又把两者推到两端，同一列里两种对齐。

档位列宽最初写死 132px，是按当前字体与文案算出来的。改成 `max-content` 的理由：
算得再准也只对这一套字体与文案成立，换个字体或标注多一个字，要么折行要么多出一条
空白。交给浏览器量，两种偏差都不会有——实测比写死的值还窄 21px，那 21px 就是
写死时多留的空白。

这一节改过两轮，值得把过程留下：

**第一轮改成了上下分段。** 理由是当时按 62/38 分栏，档位列只有一百出头，
却要装下档位名与一整句说明——必然折行。上下排能让两段都拿到整个浮层宽度。

**第二轮改回分栏。** 因为说明已经收进悬停、档位改成一行一档之后，
那条理由不再成立：档位列需要的宽度由它自己的内容定（约 110px），不是浮层的 38%。
而上下排有它自己的代价——浮层高出一截，向上弹时压住半个对话区。

顺带修掉一个上下排时期引入的问题：宽度当时用 `min-width` 抬下限，
于是浮层会一直长到 `max-width`，在 400px 的面板里几乎占满整行。改成定值
`width` 之后 `max-width` 才真正管得住它，浮层也不再随面板变宽。

**档位行另加 `flex-wrap: nowrap`。** 列宽是按当前文案算的，字体一换、
标注文案一长，算出来的余量就没了——而折行不报错，只是让「一行一档」静默失效。
`nowrap` 把失效方式从「悄悄变两行」换成「档位名截断成省略号」，行数不变。

高度那一侧不变：总高 `min(60vh, calc(100vh - 132px))`，取更紧的那个——
只靠减法不行，输入框会随内容长到 200px，那时触发按钮离视口底更远、可用高度更小，
而减法里的常数是固定的。视口矮时压缩先落在模型列（它本就可滚动），
压到 80px 下限后才轮到档位列让高度。

### 三处改成一行显示

**模型 ID 一行显示。** 此前是折行（`overflow-wrap: anywhere`），理由是「截断会让
相似名字分不清」。改掉的原因：网关的 ID 动辄四五十字符，折行让一行变两三行，
一列几十个模型翻成上百行，翻找反而更难。

浮层改成 `max-content` 之后，够宽的面板上 ID 是完整显示的，不再截断。实测：
`deepseek/deepseek-v4-flash-vision-preview`（41 字符）名字本身要 253px，加状态点、
星标、行与列表的内边距、滚动条槽位之后，面板需约 475px——470px 差 4px，480px 恰好装下。
比这更窄时仍会截断成省略号，完整 ID 在悬停说明第一行。

还要给列表预留滚动条槽位（`scrollbar-gutter: stable`）：`max-content` 那个算法
不知道这里会不会出现竖滚动条，模型一多它就出现，然后从行宽里吃掉约 15px，
最长那个 ID 的尾巴正好被裁在这 15px 里。

配套两处不能漏，漏了 `text-overflow` 根本不触发：名字自身 `min-width: 0`，
外层 `.picker-item-head` 加 `overflow: hidden`。flex 项默认不会小于内容宽度，
不写这两条时长名照旧把行顶宽，而 CSS 里那行 `text-overflow: ellipsis` 看着完全正常。

**列头一行显示。** 模型列列头装着四个元素（模型 / 名单 / 确认 / 刷新），
此前会折成两行，折出来的那一行把列表往下顶。折断的元凶是
`只看名单（本次先不收起）`——那句有一百三十来像素。

按钮文字因此都取了短名，长的说法进悬停：

| | 之前 | 现在 |
| --- | --- | --- |
| 名单开关 | `只看名单` / `只看名单（本次先不收起）` | `名单`，后一态改用虚线描边 |
| 批量确认 | `全部确认` | `确认`，作用范围进悬停 |
| 批量进度 | `停止（1/2）` | `停止 1/2` |

「开着但本次没在筛」这一态必须看得见（否则用户以为开关坏了），但它的载体从
「加长文字」换成了「虚线描边 + 悬停说明」。实测列头行数=1、无横向溢出，
在 300px 的窄面板上同样不溢出。

**档位行一行显示。** 除了列宽够，还加 `flex-wrap: nowrap` 硬保证——列宽是按当前
文案算的，字体一换余量就没了，而折行不报错，只是让「一行一档」静默失效。

### 一个只有真实渲染器才抓得到的缺陷

**CSS 里 `min-width` 永远赢过 `max-width`。** 用写死的 300px 作下限时，
把面板拖到 300px 出头，浮层就比面板宽出十几像素，右侧被静默裁掉——
body 不产生横向滚动条，那部分内容没有任何途径看到，也没有任何提示说它存在。

第一轮的修法是改成 `min(300px, calc(100vw - 24px))` 让下限自己退让；
第二轮改成定值 `width` 之后这个坑从根上没了——`max-width` 对 `width` 是有效的上限。

这条是本次在真实 WebView2 里量出来的：Node 侧的静态检查看不到布局，假 DOM 没有
计算样式，两者当时都是全绿。

### 档位一行一档

档位名在左、「会降级」短标在右，不折行，说明进悬停。

**降级标注不收进悬停**：它不是解释，是「你选的这一档在当前模型上不会生效」，
必须先看见才能选对。一期规格里「标注永不隐藏」是对模型写的，对档位同样成立。

### 「试一下」悬停才浮出

绝对定位压在行右端，默认 `opacity: 0` 且不接收点击，悬停这一行或键盘聚焦到行内
（`:focus-within`）时显形。

- 不用 `display: none`：那会让按钮浮出时行宽改变，长模型名当场重新折行，整列跳一下。
- 仍留在 DOM 里且可聚焦：键盘 Tab 得到，端到端驱动也仍找得到并 click。
- `@media (hover: none)` 下常显：触屏没有「停上去」这个动作，藏起来等于没有这个入口。

## 验证

新增 `PaneHarness --picker`：真实 WebView2 里注入三态齐全的模型列表，量算出来的
颜色、行高、行宽、`opacity` 与浮层四条边，两套主题各跑一遍。窗口尺寸可指定——
`min-width` 与 `max-height` 都只在极端尺寸下暴露问题。

7 种尺寸全部通过。实测值：不可用的模型名浅色 `rgb(180,35,24)`、深色
`rgb(242,139,130)`，各取本套调色板那一份红；档位行 26px 高、292px 宽；
「试一下」不悬停时 `opacity: 0`。矮面板下模型段守住 80px 并可滚，档位段让到 72px，
浮层未出界。

面板单测新增 `picker-legibility.test.mjs`（41 条），并变异四次确认断言会红。
`verify-picker.ps1` 的状态断言改成按字段全等比对——此前裸报状态值，而「可用」是
「不可用」的子串，「判为可用」那条断言会在其实不可用时通过。

## 没动的东西

判定的口径、探测请求的形态、名单与开关的行为、三态的含义、「标注永不隐藏」。

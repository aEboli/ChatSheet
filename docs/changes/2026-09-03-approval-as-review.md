# 2026-09-03：让「允许」成为一次核对

默认的逐项审批此前只告诉你「改哪、改多少格」，不告诉「改成什么」。这一期把审批卡
补成可核对的：给出前后对照、地址能点进 Excel、撤销不再提供点了必失败的按钮，
并把设置页摆着但执行器没实现的「每轮确认」换成有范围的本轮授权。

## 问题

```text
需要确认：写入值
Write
影响范围：Sheet1 的 2-10 行 × B-D 列，共 27 个单元格
values: 共 9 行 × 3 列          ← 只有形状
[允许] [本轮全部允许] [拒绝]
```

`summarizeArgs` 对数组只输出尺寸。更浪费的是加载项为了估算范围，已经付过一次最多
5000 格的 `read_range`，读完就把值扔了。架构文档把「diff 预览」写成选 WebView2 的
理由之一，这条路径付了 COM 的钱，预览却没出现。

另外三处让「允许」更像仪式：

- **地址是死文字**。桥通道只有 `sheet.fit`，核对要自己去 Excel 里翻。
- **撤销会说谎**。`sheet.fit` 早就立过规矩——做不到的按钮不要放——模型路径没守。
- **「每轮确认」是空壳**。选它与逐项审批走同一条路径；唯一的一键出路
  「本轮全部允许」是个布尔，格式和「新建工作表」一起放行。

## 改动

### 审批卡给出前后对照

```text
需要确认：写入值
影响范围：Sheet1 的 2-10 行 × B-D 列，共 27 个单元格   ← 可点，跳到那片格子
┌──────────────┬──────────┬──────────┐
│ 位置         │ 现在     │ 将改为   │
├──────────────┼──────────┼──────────┤
│ 第 1 行 第 1 列 │ 甲       │ 丙       │
│ 第 1 行 第 2 列 │ （空）   │ 0        │
└──────────────┴──────────┴──────────┘
另有 19 个单元格未列出。
[允许] [本轮同类允许] [含结构允许] [拒绝]
```

用的是估算影响那一次已经读到的值，不再多读一遍——审批发生在 UI 线程上，
为预览多跑一次 COM 会让大范围下的 Excel 假死，而那时卡片还没画出来。

几条边界：卡上最多 8 行 × 6 列、单格 40 字，截断用文字说明并报**剩余格数**
（截断同时发生在行与列两个方向，报行数说不全）；空单元格显示「（空）」，
与「读不到当前值」分开——前者是正常写入，后者是探测失败，合成一个样子会让人看错；
写公式对照的是公式文本而不是算出来的值；`fit_range` 省略范围时先解析已用范围，
不再留一行空白的影响范围。对照只进审批推送，不进对话历史。

### 撤销不再说谎

四处，都是「按钮亮着、点下去必然失败或什么也不还原」：

| 情形 | 此前 | 现在 |
| --- | --- | --- |
| 建图 | 不回报 Shape 名，撤销恒报「找不到图表「」」 | 回报 `Shape.Name`；取不到名字就不给按钮 |
| 建图撤销后 | 按钮变「恢复」，再点必然 UNSUPPORTED | 撤掉按钮并说明图表无法自动重建 |
| 格式全项不统一 | 标成「已撤销」而格子不动 | 不登记记录，卡片说明原因 |
| 格式部分不统一 | 当成完整撤销 | 仍给按钮，但写明「格式只能部分还原」 |

顺带修了一个 v0.7.1 就在的破坏性缺陷：**撤销会把混合填充刷成黑底。**

范围内填充不统一时，宿主对 `Interior.Pattern` 返回 DBNull，却把 `Interior.Color`
返回 **0**——那是它表示「这一项也不统一」的另一种说法，不是黑色。0 不是缺失值，
跳过缺失值的守卫拦不住它。实测一格无填充、一格青色的范围，撤销后两格都变黑，
无填充那格的 Pattern 还从 xlNone 变成实心。撤销把版面改成用户从未见过的样子，
比撤销不生效严重得多——他点它正是为了回到原样。

修法是把 Pattern 与 Color 当成一对：Pattern 读不出统一值时 Color 一并放弃。
判据也跟着改成与还原实际写不写它逐字一致，否则「能不能完整还原」这个问题
会在卡片和撤销里得到两个答案。

### 重叠的撤销先给警告

两条写入范围相交时，撤较早那次会盖掉较晚那次。乱序撤销本身是刻意保留的能力
（改 A 列与改 F 列不相干），要拦的只是**静默覆盖**：第一次点击返回警告并点出
被覆盖的是哪一次，按钮改成「仍然撤销」，再点一次才执行。

相交只按工作表名加 A1 行列区间判断，不拿 COM 代理去比——每次解析都是新代理，
Office 对象不能比标识。多区域并集（`B:B,D:D`）解析不出区间时按不相交处理，
退回今天的行为，而不是拿一个猜出来的区间去拦人。

### 「每轮确认」变成有范围的授权

授权是「工作表 + 风险类」，不再是一个布尔：

| 类 | 工具 |
| --- | --- |
| 格式 | `format_range`、`set_number_format`、`autofit_range`、`fit_range` |
| 内容 | `write_values`、`write_formulas`、`clear_range`、`sort_range`、`merge_cells`、`unmerge_cells` |
| 结构 | `add_worksheet`、`rename_worksheet`、`create_table`、`create_chart` |

三档处理方式第一次真正分开：逐项审批每次问（除非已授过本表同类）；每轮确认
本轮第一次问一次，之后同表同类不再问；全自动是唯一真正放手的档。

**结构永远不被格式或内容授权捎带放行。** 「本轮全部允许」改成「本轮同类允许」，
要放行结构必须点写明「含结构允许」的那个按钮。当前授权显示为盾牌旁的文字芯片
（`Sheet1 · 格式`），盾牌不再独自承担状态。授权只活本轮、只活在内存里——
关面板不销毁 runner，落盘会让下一本工作簿继承上一次的「允许」。

## 验证

工具层新增 19 项（建图撤销、两档格式、混合填充不刷黑、重叠警告），
地址区间 20 项，审批卡对照 16 项，面板单测新增 31 项。变异验证：
把 `Intersects` 改成恒假转红 5 条，把对照表改成恒不渲染转红 12 条，
证明断言真的在验而不是对着空节点通过。

`InteriorColor` 读成 0 这件事，是靠打印九项范围级原始读数才定位到的——
断言只说真假，分不出是造范围没造到位还是判据写错了。

# 2026-08-30：处理中的指示器换成绕圈的点

原先是横排三个脉冲点，现在是一圈八个点、一道亮度波绕着转。兜底文案由
「正在处理…」改为「正在忙着办…」。

## 为什么换

横排三点跟在「正在读取…」这类本身就带省略号的文案旁边，两处形状重复，读起来
像把省略号写了两遍。绕圈的波有明确方向感，「还在动」这件事看一眼就够。

## 参数从哪来

来自用户提供的参考视频（`lifecycle-indicator.mp4`，3308×2160、60fps、40.4s）。
本机没有 ffmpeg，用 WebView2 解码并把指定时刻的帧画进 canvas 导出成 PNG，
再逐像素分析。测得：

- 整段是 7 个静态状态，各停约 5s，状态之间是约 400ms 的动画过渡
- 只有第一个状态（1–5.5s）自身带动画，它的标签是 `Working on it...`
- 那个动画是一组小点，**周期约 0.94s**，相邻点相位差约 0.07–0.12s，
  点本身不动，只有透明度在变；亮度波从右向左推

据此取：周期 0.94s，相邻相位差 1/8 周期（0.1175s），亮态 1、暗态 0.18。

## 为什么是 8 个点而不是 12

视频里那一圈约 12 个点，但它在 3308px 宽的画面里直径约 165px。面板里这个指示器
只有 14px，12 个点的相邻间距会掉到 2.85px，小于点径 3px——整圈会糊成一条实线。
8 个点的间距是 4.21px，留得下缝。这两个数由
`tests/web/pending-ring.test.mjs` 算出来并断言，改点数时会当场报出来。

## 几何

容器 14px 见方，8 个 3px 的点定位在顶端中线，`transform-origin: 50% 7px`
落在圆心，各转 45° 的整数倍。半径 5.5px。只用一层节点排出圆周，不给每个点套壳。

相位取**负值**：取正值时首屏会有一段所有点都暗的空窗，而这个指示器往往只显示
一两秒，那段空窗会占掉可见时间的一大截。

暗态取 0.18 而不是 0：全暗的点在圈上留出缺口，缺口绕圈转比波本身更抓眼。

## 文案

只改兜底那一句。按阶段变的那几句照旧：

| 场景 | 文案 |
| --- | --- |
| 说不出具体阶段 | 正在忙着办…（改动前是「正在处理…」） |
| 思考中 | 正在思考…（不动） |
| 调工具 | 正在读取…／正在写入…（不动，按工具名组装） |
| 重试、自动续跑、停止 | 各自原有文案（不动） |

视频里是一句固定的 `Working on it...`，但把阶段文案全收成一句会丢掉「现在在读
还是在写」这个信息，那是用户在等的时候唯一能看的东西。

## 减少动效

动画一关，点会停在暗态 0.18 上，几乎看不见。因此显式恢复为全不透明，此时读作一个
静止的实心点圈——不动，但仍然在场。

选择器里「正在确认」那个点复用 `pending-pulse` 那段关键帧，换指示器时保留了它；
若顺手删掉，那个点会静默不再闪，而不会报错。

## 验证与未验证

`tests/web/pending-ring.test.mjs` 31 条：点数与 CSS 定位规则条数一致、八个角度
均分一周且互不相同、`transform-origin` 等于容器半高、相位是负的且均分周期、
暗态非零、减少动效有兜底、文案分层。变异五次确认断言会红（点数改 12、
`transform-origin` 写错、相位改正值、暗态改 0、删掉一条 `nth-child`）。

**未做目视确认。** 本环境的图片读取不可用，那圈点是否真的好看、与参考视频像不像，
只有人眼能判断。上面所有几何与相位都是算出来的，不是看出来的。

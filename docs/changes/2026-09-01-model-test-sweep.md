# 2026-09-01：批量测试时，正在测的那一行有一道扫光

批量测试模型时，当前正在测的那一行会有一道高光从左扫到右，1.1 秒一轮。

## 为什么加

批量测试一次跑几十个模型、要好一阵，而此前列表里唯一的进度线索是列头按钮上的
「停止 3/40」那个数字——看得出跑到第几个，看不出**正在测哪一个**。已测完的行会
变绿变红，正在测的那一行却和还没测的一模一样。

## 「正在测」此前压根没有标记

`is-probing` 只在用户逐个点「试一下」时置上。批量测试整批只占一次单飞闸门、
不逐个置 `probing`（那是 v0.6.0 分层设计的一部分：批内并发 5，零散确认排队等着），
所以**批量期间没有任何一行会是 `is-probing`**。当前测到哪一个只存在于
`bulkProgress().model` 里，而没有任何地方把它画出来。

因此新增 `isBulkTesting(id)`，判定放在 `model-favorites.js` 里而不是让调用方自己
比字符串：模型 ID 的大小写折叠规则（`fold`）是那个模块的私有约定，`isProbing` 也
走它。调用方直接拿 `bulkProgress().model` 跟 id 比字符串，会在网关回报的 ID 大小写
与目录里不一致时静默失配——那时行上什么都不出现，而批量测试看起来就像没在动。

## 为什么是扫光而不是闪烁

闪烁是明暗交替，和「未确认」那个闪动的状态点撞在一起：一行里两处各按自己的节奏
闪，读起来像画坏了。扫光有明确的方向，且方向本身就对应「从左往右过一遍」这件事。

高光取中性色（新增调色板变量 `--sweep`）而不是绿或琥珀：这一列的颜色已经被判定占
满了——绿是能用、红是不能用、琥珀是那个状态点。再给进度一种颜色，用户要多记一条。

不复用 `--hover` 那三档：它们是鼠标反馈，扫光是进度指示，两者强度要能各自调，
混用会让「调亮扫光」顺带把所有悬停都调亮。浅色下是压暗、深色下是提亮，方向相反
但语义一致，都是与底面分开的一道高光。

## 实现

一层 `::after` 铺满整行，`transform` 从 `translateX(-100%)` 移到 `translateX(100%)`，
渐变两端透明、中间是高光。两端各移出整行宽度，让高光完整地进和出，而不是在行内
凭空出现又凭空消失。

只动 `transform`：宽度或 `left` 变化会触发布局，而这一层在一个几十行的列表里每秒
重画多次。`pointer-events: none` 让它不挡住选中那一行。

`position: relative` 与 `overflow: hidden` 只加在 `.is-testing` 上，不动
`.picker-item` 本身——那条规则管着几十行，改它的定位与裁剪会波及整列。「试一下」
与星标是 `.picker-row` 的子节点（不在 `.picker-item` 里），所以这里的裁剪碰不到它们。

周期 1.1 秒：批量并发 5，单个模型通常一两秒内有结果。再快显得慌，再慢则一个模型
测完了光还没扫过一遍，看不出它在动。

## 减少动效

动画一关，那一层不再移动，就以一道居中的软光带静止在行上——看得见，但读不出
「这一行被标记了」。而它是批量期间「正在测哪一个」的唯一提示，因此显式改成整块
均匀高光：不动，但那一行仍然指得出来。

## 验证

- **`tests/web/chat-motion.test.mjs` 增至 87 条**：循环（与本项目其他动画相反，
  扫光必须循环，只放一次的话光扫过去就没了而那一行还在测）、周期在 0.6–2s、只动
  transform、从左到右（起始负位移、结束正位移）、两端各移出整行、渐变两端透明、
  高光走调色板变量且两套各定义一份、不吃点击、定位与裁剪只加在 `.is-testing` 上、
  减少动效有静态兜底、标记取自批量进度而不是 `isProbing`、折叠大小写。
  变异八次确认会红（改成从右到左、去掉循环、渐变换实色、两端不移出整行、
  删减动效兜底、标记错取 `isProbing`、不折叠大小写、让这一层吃点击）。
- **`PaneHarness --picker` 新增 12 条实测**（真实 WebView2，走真实的 `probe-progress`
  推送路径，不复刻渲染）：没在测的行没有扫光、被标记的行动画真的在跑且挂在
  `::after` 上、处于运行态、那一层是渐变、行被裁剪、不吃点击、同一时刻只有一行在扫、
  批量结束后收掉、另一套主题下同样在跑且用的是那一套自己的高光色。

  查伪元素上的动画必须 `getAnimations({ subtree: true })`——漏了这个参数会读到
  「没有动画」，而那与「扫光根本没接上」在结果里长得一模一样。
- 全套：网页 729 条、ToolTests 569 条、`--motion` / `--shake` / `--theme` /
  `--picker`（含 320×560 窄栏）全绿。

### 顺带修掉一个既存的飘测

`--shake` 的「产品按钮」那一组约每三次跑会红一次。原因与本次改动无关：那一组要求
浮层开着而模型列表还没到（列表一到「全部确认」就不再禁用），列表在量坐标与点击之间
到达时浮层内容位移，同一坐标换成了别的元素——实测点到过隔壁模型行上的「试一下」。
现在先看这一下究竟点在了谁身上，不是目标就明说跳过，不报「没抖」。连跑五次稳定。

# 2026-08-26：操作卡片按轮次成组，上一轮的收起来

一轮的操作卡片在下一轮开始时收成一行摘要，落在那一轮内容之后；可展开看回卡片，
也可「还原」把它们放回对话流原位。同批补了两件：一轮正常收尾留一条「已完成」，
以及补回诊断入口。

## 问题

操作卡片只按时间平铺，看不出哪些操作属于哪一轮。

```text
你：把 B 列改成日期格式
助手：好，我来改。
  ▸ 读取工作簿结构   Sheet1
  ▸ 读取范围        B1:B20
  ▸ 设置数字格式     已影响 1-20行 × B列    [撤销]
助手：改好了。
你：再按销售额降序排列
助手：正在排序…
  ▸ 读取范围        A1:D20
  ▸ 排序            已影响 1-20行 × A-D列  [撤销]
助手：排好了。
```

两条后果：

**一、一轮的操作会把对话正文挤走。** 实测三张折叠卡片占 161px，面板可视高度约 700px。
一轮四五个工具调用是常态，往前翻两轮，用户想读的回复就已经被顶出可视区。

**二、对不上账。** 核对结果时的问题是「刚才那句话，到底动了哪几个地方」。现在只能
自己从上一条用户气泡数到下一条之间的卡片——轮次边界在 DOM 里根本不存在，界面上
也只有气泡颜色这一条线索。

## 改动

```text
你：把 B 列改成日期格式
助手：好，我来改。
助手：改好了。
▸ 第 1 轮 3 个操作（1 改，2 读）                        [还原]   ← 收起，33px

你：再按销售额降序排列
助手：正在排序…
  ▸ 读取范围        A1:D20
  ▸ 排序            已影响 1-20行 × A-D列  [撤销]              ← 当前轮，平铺
助手：排好了。
```

**当前轮平铺，下一轮开始时才收上一轮。** 不在当前轮结束时收：一轮刚跑完，用户往往
正要看结果、点撤销，收在那个时候等于刚做完就把东西收走。收起后 33px，比平铺的 161px
省下 128px——那正是被挤掉的正文高度。

**组落在那一轮内容之后，不搬到对话流底部。** 操作跟着它所属的那轮对话走，
「查看某轮对应的操作」才是就地展开。搬到底部的话就成了去别处找，而且几轮之后
底部会积起一叠彼此无关的组。

**摘要给统计，不只给条数。** 合上一轮之后要判断的是「那一轮动过表没有」，
「1 改」直接回答了它，「3 个操作」回答不了。改/读的分类用加载项在 `tool-start` 里
已经给出的 `risk` 字段，不在面板另立一套判定；`Write` 与 `Structure` 都归「改」——
摘要要回答的是动没动表，分两类反而要多读一遍才知道加起来是几。

**组里有失败时摘要标红。** 失败的卡片本来会自动展开，但它在收起的组里看不见。
组上不留记号的话，用户合上一轮之后就再也不知道那轮里出过错。同理，成组之后点撤销
也要刷新摘要里的「已撤销」计数——收起时那是唯一可见的说法。

**「还原」把这一组放回原位。** 用途是核对时机：想确认「模型说这句话之前先读了什么」，
只有卡片穿插在回复之间才看得出来。还原过的不再被后续轮次收回去——那是用户明确表达的
「我要看原位」。

**手动操作归入所在那一批。** 面板上点「适配」产生的卡片可能落在两轮之间，它不属于
任何一轮，但确实发生在这段时间里。按批收集就不必为它另立一类：从上一轮开始到下一轮
开始之间发生的操作是同一批，谁发起的由卡片上的「手动」标记区分。一轮都还没跑过就点了
适配，那一组的摘要写「手动操作」而不是「第 N 轮」。

## 还原为什么要记挂载序号

还原要把卡片放回原来的位置，而「原来的位置」得有个表示方式。记「插在谁后面」是不够的：

```text
第 1 轮：气泡A 卡片1 气泡B 卡片2 气泡C
第 2 轮开始 → 卡片1、卡片2 收进组，组落在气泡C 之后
第 3 轮开始 → 组、气泡C 等又都被后面的内容推上去
此时还原第 1 组：卡片1 该插在气泡A 之后——但如果锚点本身也进了某个组，就找不到落点
```

改成每个上屏的节点记一个递增的挂载序号（`dataset.seq`，由 `mountToTranscript` 统一
写入），还原时把整条对话流按序号重排。序号是节点自己的属性，不依赖邻居是否还在原处，
因此无论此前形成过几个组、还原过几次，重排结果都是当初的上屏顺序。

代价是所有进对话流的东西都必须走 `mountToTranscript`，漏一个它就没有序号，
还原时会被当成最早的节点排到最前面。九个上屏点已全部改过。

## 同批补的：一轮正常收尾留一条「已完成」

加载项有五条终止路径，其中四条各留一条居中胶囊：被停止、达步数上限、反复截断后放弃、
出错。第五条——正常跑完——原先什么都不留。于是屏幕上这两种分不开：

```text
助手：我已经把 B 列改成日期格式了。          ← 真做完了
助手：我先读一下 B 列的现有格式，然后……       ← 被截断，最后半句读着像交代
```

第二种尤其难辨：模型被长度上限截断时，最后那半句往往正好像个结论。要确认「这轮完没完」
只能翻日志，而那行日志本身也不可信（见记忆里「一轮提前结束怎么定性」）。

现在正常收尾插一条「已完成」，位置与错误、停止那几条完全相同，用主色那一档
（`--accent-bg` / `--accent-border` / `--accent-text`），与琥珀的警示、红的错误
并列成第三档。描边取 `accent-border` 而非满饱和度的 `accent`：正常收尾是最常出现的
一条，描边和文字都用主色会比错误还抢眼。

**要害是互斥。** 只在 `turn-complete` 里插——加载项那五条路径互斥，`stalled`、
`step-limit`、`stopped`、`error` 各自 `return` 而不再发 `turn-complete`。冒出一条
「已停止」紧跟着「已完成」比什么都不显示更糟：两条自相矛盾的收尾，用户不知道信哪个。
`turn-complete-mark.test.mjs` 里四条异常路径各有一组断言盯着这件事。

**这条标记的用处主要在它不出现的时候**，所以悬停说明把这层意思写出来：
「这一轮已正常结束。没有这一条就说明中途断了（被停止、达上限或出错）」。

**它必须是每轮的最后一行。** 轮次组在下一轮开始时形成，本来会追加到它后面，那样
读下来是「回复 → 已完成 → 一组操作」，收尾之后又冒出内容，而用户扫「这轮完没完」
正是找那条胶囊。成组时把标记重新挂到末尾——`mountToTranscript` 会同时刷新它的挂载
序号，于是还原时按序号重排的结果与此刻的顺序一致，两处不会打架。

被停止那一轮不做这件事：它没有完成标记，组落在停止说明之后即可。只特判完成标记一种，
是因为它有专门的类名（`notice-complete`）；错误胶囊则可能出现在一轮中间——工具失败、
审批失败都会插一条——分不出哪条才是终止的那条。

## 顺带补回诊断入口

做主题切换那次把诊断从导航栏撤了（三个页签会把标题挤掉，而它是出问题时才去一次的
地方）。但面板里因此没有任何可点的入口，只剩功能区那个按钮——设置页的「排查」区
还写着「点功能区里的诊断按钮」，等于提到了一个页却没给路。

这次在那段说明下面直接放一个「打开诊断」按钮。改 hash 而不是直接调用路由函数：
`app.js` 监听 `hashchange`，由它统一决定怎么切页，两个模块不必互相引用。
导航栏保持两个页签不动。

## 假 DOM 要做实的两处

新增的 `ops-group.test.mjs` 里有两件事必须做实，否则测不到东西：

**一、`append` 要把节点从原父节点摘走。** 成组就是把卡片从对话流搬进组里，真实 DOM
会自动解除原来的父子关系。假 DOM 不解除的话卡片会同时出现在两处，「组落在哪」
「组外还剩几张」全都失真。

**二、`querySelector` 要认 `.tool-card[data-tool-id="…"]`。** 工具结果靠它把卡片找回来
填充（`finishToolCard`）。只认类名的话这个选择器永远返回 `null`，卡片一直停在
「执行中…」——撤销按钮、失败标记、自动展开都不会出现，于是后面那些断言测的是
一堆空卡片，而且全都会「通过」。这一条正是本次写测试时先踩到的。

# 2026-09-04：系统提示注入本机当前时间

模型没有时钟。「日期写今天」会得到一个训练数据截止前后的日期：形态合法、不报错、也不会有任何工具返回值来纠正它。实测 2026-09-04 当天写出 `2026-01-19`。

## 问题

系统提示里有工作簿结构和选区，没有时间。相对说法（今天、本月、三天后）只能靠模型自己猜，猜错了用户不逐格核对就发现不了。

顾问模式同样受影响：它给不出工具调用，但公式与操作步骤里的日期一样会写错。

## 改动

每轮刷新系统提示时写入本机当前时间，三种工具形态共用。

```text
## 当前时间
- 现在是 2026-09-04 星期五 14:37（用户本地时间，时区 UTC+08:00）。
- 这是唯一可信的时间来源。……相对说法一律以此为基准推算……
- 写日期进单元格时：要固定值就写出具体日期；要「每次打开都显示当天」才用 =TODAY() 或 =NOW()。没说清楚时按固定值写。
```

放在工作簿信息之前：两段都是每轮重采的事实，归在一起；结尾位置也最不容易在长上下文里被冲掉。

几处取舍：

- **精确到分，不写秒。** 秒级没有用处，还会让每轮系统提示都不一样。
- **星期名写死中文。** 这台机器的区域设置未必是中文，混出 `Friday` 会让模型跟着换语言。
- **时区写成 `UTC+08:00`。** 不依赖区域设置；半小时时区也能写出分钟。
- **不另开 `get_current_time` 工具。** 顾问模式发不出工具调用，而「今天是哪天」三种形态都需要。时间随系统提示每轮刷新，足够用。
- **没说清楚时按固定值写。** 「写今天」多数是要一个不会自己变的日期；塞 `=TODAY()` 会让打开工作簿的那天变成别的日子。

`SystemPrompt.Build` 多一个可选的 `now` 参数，默认取本机时间。测试要能钉住一个固定时刻，否则断言得跟着真实时钟走。

## 验证

```powershell
dotnet build ChatSheet.sln -c Release
.\tests\ChatSheet.ToolTests\bin\Release\ChatSheet.ToolTests.exe
```

新增 `tests/ChatSheet.ToolTests/SystemPromptTests.cs`，钉住 `2026-09-04 14:37:52 UTC+08:00`，锁住十六件事：日期、时刻、不写到秒、星期五/星期日映射、不写英文星期名、东八区/西五区/半小时时区、唯一可信来源、相对说法、固定值与 TODAY 的区分、三种工具形态都带这一段、位置在工作簿信息之前。

断言反过来验过两次：星期名数组整体右移一位会失败 2 条；整段不写入会失败 14 条（只剩「不写到秒」这条否定断言）。

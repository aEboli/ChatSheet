# 2026-08-25：合并单元格工具

工具清单里补上 `merge_cells` 与 `unmerge_cells`。两者都可撤销，其中合并被丢弃的值
会在撤销时找回。

## 问题

用户要求合并单元格，模型回答自己做不到，并准确复述了自己能做的事：读写值和公式、
字体、填充、对齐、数字格式、排序、建表格图表，唯独没有合并。

这个回答没说错。错的是清单——合并单元格是 Excel 排版最常用的操作之一，做标题行
几乎绕不开，功能区上它是一个按钮。所谓「能力有局限」不是模型的局限，是这个项目
当初没把它放进那个受限集合。

它被漏掉的原因大概也不是难，而是它在所有写操作里的特殊性：**这是唯一会静默丢数据
的一个。** 宿主只保留左上角单元格的值，其余一概丢弃，事后没有任何迹象可查——
不像清除内容那样一眼能看出少了什么。这一点决定了它该怎么加，而不该不加。

## 改动

两个工具，风险级别都是 `Write`，因此默认逐项审批并在审批卡里显示影响范围。

```text
merge_cells   range, sheet, across, horizontal_alignment, vertical_alignment
unmerge_cells range, sheet
```

`across` 为真时逐行分别合并（每行合成一格，行与行不相连），为假时整片合成一格。

对齐是可选参数而不是另一次调用：功能区上「合并后居中」是一个按钮，用户说「合并」
时想要的往往就是那个效果。分成 `merge_cells` + `format_range` 两次会留下两条撤销
记录，用户点一次却要撤两次——这正是当初把 `fit_range` 合成一个工具要避免的事。
但默认不改对齐：已经排好版的表不该因为合并一个标题就被重新对齐。

对齐值在动手之前解析。顺序反了的话，非法值会在合并已经生效、值已经丢掉之后才报错。

## 围绕「会丢值」做的三件事

**合并前先数清楚要丢什么。** 工具在动手前整片读一次 `Value2`，数出非锚点位置上的
非空单元格个数，作为 `discarded_values` 回报给模型。整片读一次比逐格问宿主快得多，
而 5,000 格的上限让这一次读的成本可控。这个数字是模型判断「该不该先问用户」的唯一
依据，因为丢值之后无从查证。工具说明里也写明了合并前应先读一遍范围。

同时回报 `merged_areas` 与 `areas`：宿主可能把范围外已有的合并一并吞进来，
只报告「已合并」会让模型以为版面就是它请求的样子。

**撤销要把值找回来，而不只是把格子拆开。** 合并的快照是
`Content | Format | Merge`——内容逐格留底才能还原被丢的值，`Format` 因为工具可能
同时改对齐，`Merge` 用来记下范围内原有的合并区域（用户可能是在已有合并的版面上
再合一次）。

内容逐格留底意味着受 5,000 单元格上限约束。超限时**拒绝执行**并报
`RANGE_TOO_LARGE`，而不是像 `fit_range` 那样放行但不承诺撤销——`fit_range` 最坏
是版面变了，用户看得见也改得回来；合并最坏是值没了，且看不出没了什么。

取消合并不丢数据（原内容留在左上角，其余格本就是空的），所以快照只记 `Merge`。

**还原的顺序不能反。** 合并区域里只有左上角一格可写，向其余格写值会被宿主拒绝
（报「要求合并单元格具有相同大小」）。因此 `Restore` 在有合并快照时先把范围拆平，
让整片格子重新可写，再还原内容与格式，最后照原样合回去。

## 三处容易忽略的细节

**宿主的确认框会冻住整个 Excel。** 合并含多值的范围时 Excel 会弹「仅保留左上角的
值」。加载项跑在宿主 UI 线程上，弹框会把 Excel 连同面板一起冻住，而那个框没有人能
点——用户的许可已经由面板的审批卡收过一次。合并与合并还原期间关掉 `DisplayAlerts`，
之后还原原值。

**没有「列出这片里的合并区域」这样的成员。** 采集合并区域只能逐格读 `MergeArea`
再按地址去重。范围级 `MergeCells` 返回 `false` 时可以一次断定没有合并，这是常见
情形；返回 `true` 或 `Null`（范围内不统一）时才逐格问。因此 `Merge` 这个维度也算
「逐格」，和内容、格式一样受单元格上限约束——否则取消合并一个 26,000 格的范围会
悄悄逐格问两万多次。

**跨界的合并区域要整块记。** 逐格读到的区域地址可能越出快照范围（比如范围只到
B1，而 A1:C1 是一块合并）。整块记下来，否则还原时会把它复原成半块，比不还原更糟。

**空列表与 null 不是一回事。** `MergeAreas` 为空列表表示「采过，当时没有合并」，
还原时要把范围拆平；为 null 表示这个维度没采，还原时不该碰合并状态。

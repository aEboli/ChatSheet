# 2026-08-25：双击式安装器

根目录加 `install.bat`，双击打开菜单，输入编号选择安装、卸载、诊断。

## 问题

安装的唯一入口是一行命令，对不用命令行的人有三处门槛：得知道怎么在解压目录里
打开 PowerShell、得原样敲对包括 `-ExecutionPolicy Bypass` 在内的全部参数、
还得知道换成 `uninstall` 或 `diagnose` 才能做另外两件事。

而 `.ps1` 双击是打不开的：Windows 会用编辑器打开它，默认执行策略也会拦下来。
所以这个只有三个操作的项目，一个不用记命令的入口都没有。

## 改动

```text
  当前状态：已安装 0.2.1.0（2026-08-25 18:26）
  运行模式：源码检出（安装前会先构建，需要 .NET SDK）
  安装位置：C:\Users\Administrator\AppData\Local\ChatSheet\app

  [1] 安装或更新    覆盖安装并注册，Excel 需重启才生效
  [2] 卸载          反注册并删除安装目录，保留日志与设置
  [3] 诊断          检查运行时、COM 注册、宿主登记与日志
  [4] 退出
```

先报三件事再给选项：装的是哪个版本、当前是源码检出还是预构建发行包（决定「安装」
会不会先 `dotnet build`）、装到哪里去。这是判断「我点 1 会发生什么」的依据。

`install.ps1` 一行没改，仍是真正干活的脚本；菜单只负责问清楚做哪件事。
根目录到 `scripts/` 的相对位置在源码检出和发行包里一样，所以同一个 `.bat`
两种布局都能用，不必为发行包单独做一份——打包后的副本实测会正确识别成
「预构建发行包」。

## 三个坑

**提权必须在菜单启动时做。** `install.ps1` 未提权时会经 UAC 重启自身，跑完
`exit` 整个进程——菜单会跟着一起消失，用户点一次就没了。改成菜单启动时提一次，
之后每个动作都在同一个窗口里跑完。代价是只想诊断的人也要授权一次；为此把菜单拆成
两种权限只会多一次弹窗和一次解释。

**动作要用 `&` 调用，不能点源。** `exit` 在被 `&` 调用的脚本里只结束它自己，
点源会把菜单一起带走——与上一条是同一个坑的另一面。输入 3 跑完诊断还能回到菜单，
就是在验这件事。

**编码有两层，方向相反。** `.bat` 被控制台按 OEM 代码页（中文 Windows 上是 936）
读，中文写在里面会乱码甚至让解析器出错，所以它只做转发，一个非 ASCII 字符都没有；
而 `menu.ps1` 必须是**带 BOM** 的 UTF-8——PowerShell 5.1 读无 BOM 的文件时按 ANSI
解释，中文照样乱码。后者是仓库里其他 `.ps1` 已有的约定（`install.ps1` 等都带 BOM）。

顺带一个小坑：Git Bash 的 `grep` 在文本模式下会吃掉 `\r`，用它数 CRLF 会得到 0，
看起来像是换行符没写对。要用 `grep -U`。

## 涉及文件

| 文件 | 改动 |

| `install.bat` | 新增。纯 ASCII + CRLF，转发给 `menu.ps1` |
| `scripts/menu.ps1` | 新增。编号菜单、自我提权、状态检测 |

## 验证

- 菜单渲染与状态检测正常，中文显示无误
- 非法输入（`9`、空回车）提示后重新给选项，不退出
- 输入 3 诊断在同一窗口跑完并返回菜单
- `package-release.ps1` 实跑：`install.bat` 在包根、`menu.ps1` 在 `scripts\`，
  都进了 `SHA256SUMS.txt`，编码分别保持 ASCII 与 BOM
- 打包副本单独运行，正确识别为预构建发行包
- 未跑：输入 1 / 2 会真正改注册表与安装目录，本次未在菜单里执行；
  安装路径本身在上一次变更里已实跑验证

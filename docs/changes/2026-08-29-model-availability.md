# 2026-08-29：常用模型名单与从真实对话里学到的可用性

选择器现在会标出哪几个模型真能用，把常用的排到最前面，并提供一个开关把列表收窄到
名单内。判定全部来自用户已经付过钱的那一轮对话，不额外发任何请求。

## 问题

模型选择器把 `GET /models` 返回的 ID 原样列出来。网关动辄返回几十上百个，其中能用
的往往只有两三个：有的没有配额，有的账号无权限，有的只是别名，有的一发就 404。
用户要确认哪个能用，唯一的办法是选中它、发一句话、看报什么错——错了再换下一个。

问题的根子在于协议本身不提供答案，`CapabilitySignals.cs` 的注释里早就记下了这件事：
没有任何协议提供「该模型支持什么」的查询接口，`GET /models` 只给名字。

于是「不可用」此前只有一个信号来源：真实对话失败后的启发式。它是被动的、事后的，
而且结论随进程消失，也从未呈现给用户——上一次踩过的坑，下一次还要再踩一遍。

两件事被混在一起：「我常用哪几个」是用户的选择，稳定、跨会话成立；「这个模型现在
能不能用」是外部事实，会随配额重置与网关调整而变。合成一张表会同时做错两头。

## 改动

### 判定只从真实对话里来

- **可用**：本轮收到过任何流式事件。到达了模型就是可用性的全部主张。
- **不可用**：本轮失败，且服务端原文点名了这个模型。
- **未知**：其余一切，也是任何拿不准情形的归宿。
- 从没发过一轮的模型没有判定，显示为「未确认」。

零额外请求就覆盖了用户真正用过的每一个模型。

刻意不把「支持工具调用」算进可用性：既有规范已经明确，模型连指令块都写不对时仍然
继续服务，改为给出公式与操作步骤。也就是说**不支持工具的模型是可用的**。

### 判据读服务端原文，不读 `Message`

这是本次唯一的接入层改动，也是判定能不能成立的前提。

`BuildHttpErrorAsync` 会把本地拼的提示塞进 `Message`，而 `HintFor(404)` 返回的是
「请检查接口地址与模型名是否正确」——**含「模型名」二字**。而 `ProviderException`
此前只有 `Code`、`Message`、`RetryAfter`，没有保留未拼装的原文。

照既有风格加中文 needle 去认「点名模型」，我们自己的提示就会把每一个 404 都喂成
假阳性：地址填错的裸 404 会给名单里每个模型依次判死刑。

因此给 `ProviderException` 增加只含服务端原文的 `Detail`，判定只读它；`Message`
的拼装一字不改。裸 404 因此判未知。

判据还刻意**不做**「原文出现过模型名」这类兜底——试过，不成立：网关报参数错误时常
把整个请求体回显在原文里，而请求体必然含 `"model":"gpt-4o"`，于是每条这样的 400
都会被读成点名了模型。测试里留了这条反例。

### 顺路修一个现存缺陷

`LooksLikeVisionUnsupported` 匹配裸子串 `"image"`。选一个名字里带 `image` 的模型
（`gpt-image-1`）、附一张图、发送：那句 `model 'gpt-image-1' does not exist` 是 4xx
且含 `image`，于是被记成「不支持图片输入」，白花一次视觉中转请求去描述图片、剥掉
所有图、再用同一个不存在的模型重试一遍，最后告诉用户「当前模型没有视觉能力」。

这个缺陷在本次改动前就在。新增的可用性标记会把同一条错误正确读成「不可用」，于是
同一行上出现两个互相矛盾的标记——是新标记把它照出来的。

补上镜像判据：错误点名了模型时，它不是任何能力信号。既有代码已有反方向的同类守卫
（工具判据先排除视觉错误），这是第三条。

### 名单落盘，判定不落盘

名单是用户意图，落盘；判定是外部事实，只在内存里。

名单另存 `favorite-models.json` 而不进 `settings.json`：后者的 `Save` 按白名单整体
重建文档，任何只读不写的键会被下一次任意写入方（面板宽度、主题都算）抹掉。

原子写用 `File.Replace` 而**不**照抄 `Settings.cs` 的 Delete + Move：后者在两步之间
崩溃会同时失去新旧两份。设置丢了只是回默认值，名单丢了是用户手工标注的成果没了。
`File.Replace` 一次替换并顺带留下 `.bak`。

分组文件里「归属不一致」是常态而非错误，因此只校验当前连接那一组，其余组按字节原样
保留。这与既有的 `DropModelFromOtherConnection` 处置**不同**——那是为「只存一个模型」
写的，直接照搬会在读盘时删掉其他所有连接的分组。

本机 CLI 按**解析后**的 CliKind 归组，而不是配置里的 `CliSource`：把下拉从「自动」
钉成「Claude」时凭据一模一样，而连接键会变，名单会原地失联且旧分组够不着。

刻意**不**记地址：读不到地址与「就是官方地址」分不开（`TryReadCodexBaseUrl` 吞掉
异常返回 null，调用方补上官方端点），而且 token 缺失时连地址都拿不到。失效交给下面
那条展示期阀门。

### 判定的作用域是 Excel 进程，不是「面板会话」

如实写作用域，因为代码做不到后者：`EnsurePane` 是 `if (_pane != null) return;`，
关闭面板只改 `IsVisible`，控件不销毁、`AgentChannels` 不重建，而档案字典是进程级
静态字段。既有能力档案的注释写着「重开面板重探一次」，代码从来没有兑现过。

换连接或写入密钥时作废该连接的判定。本机 CLI 的密钥在 CLI 自己的配置里、不经
`SecretStore`，那条路上没有这个触发点——不是漏了，代码里写了注释。

### 排序无条件生效，开关不会把人锁在外面

名单里的模型排在目录之前，不需要任何开关，什么都不藏。判定到达不改变行序——一个
标记忽然出现就让行跳走，比没有标记更难用。

开关默认关。阀门只有一条，但同时管住空名单与全部失效：**开关开着而名单里没有一个
模型出现在当前目录里时，显示完整目录**。少了这条，换过网关或模型下架之后开关一开，
选择器就只剩当前模型，而能用的那些全被收起来了。

当前选中的模型永远可见。刚标第一颗星时不当场收起其余的——用户的动作是「记住这个」，
效果却成了「藏起另外几十个」。

开关走 `session.update` 而不是 `settings.save`，并且**要**加进 `settings.js` 的只读
字段删除名单：`current` 是面板启动时的快照（`initSettings` 每个面板生命周期只跑
一次），不删就会在设置页保存时把刚拨的开关写回旧值。

### 大小写口径

新增的判定缓存与名单一律忽略大小写，面板侧比较也折叠后再比。此前三处不一致：
能力档案用 `Ordinal`、目录去重用 `OrdinalIgnoreCase`、面板的 `includes` 区分大小写。
手填 `GPT-4O` 而目录里是 `gpt-4o` 时，判定会落在一个键上而行渲染查另一个键。

刻意不改能力档案的比较器——那是既有回退链的行为，不在本次范围内。

## 面板

`.picker-item` 保持 `<button>`、class 与点击语义不动，外面套一层 `.picker-row`，
星标作兄弟节点：HTML 禁止按钮里嵌按钮，而宿主的端到端驱动按 `.picker-item-name`
的 textContent 全等匹配后调 `row.click()`，把它降级成 div 会让那条路径失效。

模型行另起 `buildModelRow`，不给两列共用的 `buildRow` 加参数——否则思考等级行也会
长出星标与状态点。

摘要行的「不可用」新增 `.picker-model.is-unavailable`，不复用
`.picker-thinking.is-downgraded`：后者按 `.picker-thinking` 限定作用域，只搬类名
会没有样式而且不报错。

被收起的数量放列表底部而不是列头：列头再塞内容会把列表顶出浮层，而浮层是
`overflow: hidden`，超出部分会被静默裁掉、现有自检一条都不会报。

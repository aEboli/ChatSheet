# 2026-09-01：点了点不动的按钮，横向抖一下

禁用的按钮点下去什么都不发生，而「什么都不发生」既可能是拒绝、也可能是没点中、
或者程序卡住了——三种情形对用户是同一种体验。现在点禁用按钮会让它横向抖 0.19 秒。

覆盖面板里所有禁用按钮，共六处会进入禁用态：发送、撤销、批量确认、批量测试、
设置页的取模型与保存、审批卡片的三个按钮。以后新加的也自动覆盖（见下）。

## 参数从哪来

用户提供的参考视频 `shake-disabled-button-while-clicking.mp4`
（8.96s、1852×1080、60fps、535 帧，存于 `work/refs/`）。本机没有 ffmpeg 也没有
图像库，所以照旧走「WebView2 解码 + canvas 导出 PNG + zlib 逐像素算」这条路
（`work/refs/grabber/` 与 `work/refs/analyse.mjs`）。

视频里是一个直径 461px 的灰色圆按钮，被连点四次，每次抖一下。取其中两次逐帧量：

| 量 | 事件一（1.5s） | 事件二（2.94s） |
| --- | --- | --- |
| 时长 | 1508→1692ms = **184ms** | 2942→3125ms = **183ms** |
| 峰值偏移 | -56.3px | -59.7px |
| 方向反转 | 5 次（6 个半程） | 5 次 |
| 首个半程 | 向左 | 向左 |
| 弦宽变化 | <2% | <2% |
| 竖向偏移 | ±0.5px（噪声） | — |
| 圆内颜色 | 恒 rgb(128,128,128) | — |

据此：**纯水平平移，不缩放、不变色、不动竖轴**。取 0.19s、6 个半程（半程约
31ms，即周期约 62ms）、首程向左。

振幅包络归一化后是 1.0、0.7、0.6、0.6、0.3、0.3。60fps 下每个半程只有约 1.8 帧，
峰值必然被采样漏掉一部分，因此包络精度约 ±0.1——第三四程与第五六程各自相等，
是这个精度下读到的样子，不是刻意设计。

### 幅度为什么用定值 3px 而不是按比例

参考视频里 56/461 ≈ 12.6% 是那个按钮自己的比例。面板里最常见的禁用按钮是 26px
见方的图标按钮，3px 恰好是 11.5%，与参考相当。而设置页那种一百多像素宽的按钮
若也按 12.6% 就是 15px，横向甩出去半个按钮宽——抖动幅度在实现里向来是绝对值，
不随元素变大。

### 怎么量的（几个有用的手法）

- **定位动画元素**：算相邻帧变化像素的包围盒，直接给出坐标，比在字符画上目测可靠。
- **量位移**：取一条穿过元素、避开鼠标指针的扫描线，找左右边缘，边缘两侧灰度
  线性插值到亚像素——抖动只有几十像素，整像素分辨率读不出曲线形状。
  同时报弦宽，顺便就能判断有没有缩放。
- **帧率**：`video.requestVideoFrameCallback` 给出每帧的 mediaTime，那是权威值。
  一开始按固定步长 seek 取帧，落帧不确定，位移序列读出来是乱跳的——先问清帧率
  再按帧中心取样才对上。

## 禁用按钮不派发点击事件

这是实现上唯一的难点：**绑在禁用按钮上的 click / pointerdown 一次也不会来**，
而那正是「点了没反应」的根源。所以监听装在文档上（捕获阶段），用
`document.elementFromPoint` 问「指针落点下面是不是一个禁用按钮」——
事件从禁用按钮身上不冒泡，但指针命中测试照常命中它。

用 `pointerdown` 而不是 `click`：click 在禁用按钮上根本不会产生，连它的祖先也
收不到。装在文档上还有个好处：一次覆盖全部六处，也覆盖以后新加的；逐处绑等于
每次新增都要记得再绑一遍。

`aria-disabled="true"` 一并认——那是「看得见、点不动」的另一种写法，
用它的控件仍然可点可聚焦，反馈同样该给。

顺带把按下微缩改成只对可点的按钮（`.icon-btn:not(:disabled):active`）：
禁用的按钮没有「按下」这件事，缩一下等于说点成了。

## 真实鼠标实测抓到的一个缺陷

`animationcancel` 是**异步派发**的。连点时 `playRefusal` 为了重放会先摘类，
那一下让运行中的动画被取消；等 cancel 事件到达，重放的新动画已经在跑了——
清理处理器若无条件摘类，就把刚加上的类又摘掉，第二下点击于是毫无反馈。

真实鼠标连点两下、只抖一次，就是这个原因。修法是摘之前先确认此刻真的没有抖动
在跑（`getAnimations()` 里找 `refuse-shake`）。

这个缺陷只有真实指针输入才暴露：`dispatchEvent` 造的事件不走命中测试，怎么造都
能通过，那样测的是我自己的假设而不是浏览器的行为。

## 验证与未验证

- **`PaneHarness --shake`（真实鼠标输入）11 条。** 用 `SetCursorPos` +
  `mouse_event` 真的点下去：命中测试拿得到禁用按钮、点击到达页面、抖动起播、
  放完、类摘掉、连点两下抖两次、可点的按钮不抖。每条「抖没抖」的断言前面都有
  一条「点到了没」的前置断言——点偏时两者报的是不同的事。
  也接进了 COM 自动化（`DriveMotionForTest`）。
- **`tests/web/chat-motion.test.mjs` 增至 72 条**：抖动只动 transform 且只动横轴、
  6 个半程、首程向左、方向逐程交替、振幅不回升且峰值在首程、半程间隔均匀、
  首末回原位、只声明一次 animation、监听用 pointerdown + 捕获 + elementFromPoint、
  同时认 aria-disabled、连点重放顺序、清理前先确认没有动画在跑。
  变异八次确认会红（首程改向右、振幅回升、改成竖向、删两个半程、终点不回原位、
  改用 click、无条件摘类、禁用也微缩）。
- 全套 24 个网页测试 714 条、ToolTests 569 条、`--motion` / `--theme` / `--picker`
  全绿。已构建 Release 并安装，核对过安装目录里那份是新的。
- 踩到并记下的两个坑：150% 缩放下 CSS 像素要乘 `devicePixelRatio` 才能换成
  屏幕坐标（第一次点偏了三分之一，还把浮层点关了，而断言只报「没抖」）；
  用产品按钮做连点测试会撞上模型列表异步到达导致的浮层位移，第二下点到了隔壁的
  「试一下」，真起了一次探测——连点改用位置固定的注入按钮。
- **未做目视确认。** 本环境读不了图片，抖动的观感与参考视频像不像，只有人眼能
  判断。上面所有参数都是从视频像素里量出来的，不是看出来的。

# 国际版本机授权与倍率修复

本次修复已有授权复用与倍率展示功能，版本为 `0.10.3.7`。

## 问题与证据

- 本机国际版安装在 `C:\Program Files\WorkBuddyAI`。官方 `cli/product.json` 标明产品为 `WorkBuddy AI`、地址为 `https://www.workbuddy.ai`、用户目录为 `.workbuddy-ai`；旧代码却把它归入国内版，国际版读取的是独立 CLI 的 `.codebuddy`。
- 通过国际版桌面端 ACP `session/new` 可直接读取现有授权和 20 个模型，无需浏览器重新登录。旧候选路径返回独立 CLI 的 17 个模型。
- 官方 ACP 部分倍率为 `x0.34 credits`，旧解析只接受 `x0.34`，因而丢失这类倍率。
- 官方 CLI 的 `authenticate` 会先退出已有账号；设置页切换模式后只检查组件，尚未读取账号便显示登录入口，容易触发不必要的重新授权。

## 修复

- 将 WorkBuddyAI 和其 Node 运行时归入国际版，优先复用对应桌面端，独立 CLI 作为后备。
- 普通登录先检查已有授权；只有用户明确点击“切换账号”时跳过复用并重新授权。
- 接入模式切换后自动读取该模式的授权和模型，继续按模式代数拒绝迟到响应。
- 兼容官方 `credits` 单位，保留零倍率；Auto 等缺少倍率的模型不补造数值。
- 登录态继续由官方组件保存，ChatSheet 不读取、复制或保存第三方令牌。`--no-session-persistence` 只影响 CLI 对话记录，不关闭账号授权存储。

## 验证

- 修复前的定向回归准确复现三项失败：WorkBuddyAI 产品分类、国内候选隔离、带单位倍率解析；修复后均通过。
- `dotnet build ChatSheet.sln --configuration Release --nologo --verbosity quiet`：零警告、零错误。
- WorkBuddy 账号与 ACP 对话测试，以及授权目录、模式切换、模型目录和版本网页测试通过。
- 实机先运行普通登录，再从另一个进程重新读取目录：复用 `.workbuddy-ai`，未触发浏览器重新授权；返回 20 个模型，其中 19 个具有官方倍率，Auto 无倍率。
- 真实 WebView2 面板验证设置与对话倍率、窄面板布局、切回国际模式后恢复登录，以及普通登录和切换账号的请求区别。测试拦截重新授权请求，不登出用户账号。
- 本机安装完成后，32 位进程加载实际安装的 `0.10.3.7` 程序集，确认授权可复用；当次官方目录返回 21 个模型、20 个有效倍率（目录随服务端更新）。Excel/WPS 的 x86 与 x64 COM 注册自检通过。

未替用户执行 Google/GitHub 退出和重新登录；第三方页面自身的账号选择及授权过期策略仍由官方服务决定。

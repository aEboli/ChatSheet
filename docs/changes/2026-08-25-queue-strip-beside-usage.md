# 2026-08-25：排队条移到本轮用量旁

排队中的输入不再一提交就变成对话气泡。改为显示在输入区上方那一行、与
「本轮 xxx 入 / xxx 出」并排、居中靠左的排队条上；多条依次向上叠，
轮到哪条才把它挪进对话流。

## 问题

用户的说法是「排队会自动进入对话框，而不是一直显示」。这里有两层：

**位置不对。** 对话流记录的是已经发生的事。还没发出去的内容混在里面，即便带虚线
边框和「排队中 · 第 2 位」的标记，读起来仍像已经处理过的一条。

**看不住。** 气泡跟着对话流滚动。上一轮一边跑一边产出回复与工具卡片，排队的那条
很快被顶出可视区。用户此时想确认的恰恰是「刚排的还在不在、排第几」，却要往上翻。

## 改动

```text
┌─────────────────────────────┐
│  对话流（已经发生的事）      │
│  ...                        │
│  ┌ 助手回复 ─────────┐      │
│  └───────────────────┘      │
├─────────────────────────────┤
│           ⌐2 顺便加一列… ×   │   ← 越早排的越靠上
│           ⌐1 再把 B 列… ×    │   ← 下一个就发这条
│  状态          本轮 812 入 / 96 出 │
├─────────────────────────────┤
│  输入框                      │
└─────────────────────────────┘
```

排队条用 `column-reverse` 向上生长，队首贴着输入区：最下面那条就是马上要发生的事，
与队列往下流动的方向一致。队列为空时整条收起，不占竖向空间。状态与用量底边对齐，
位置不随队列长度上下跳。

一条排队项在窄栏里只占一行：位次数字、截断成一行的正文、附件数、取消。完整正文与
「排在第几位」放进悬停说明——这一行的横向余量本就要与状态、用量分，写全会把它挤到
换行，而换行吃掉的是对话区的高度。

轮到某条时它才进对话流，于是同一条同一时刻只出现在一处：待办在排队条上，已发生的
在对话流里。取消仍保留原文——那段文字是用户写的，丢了只能重新想一遍——被取消的落进
对话流末尾并划掉、标明未发送，可以直接复制回输入框。新会话时不留痕，因为对话流
下一步就要清空。

队列本身的语义一个字没动：仍是面板侧 FIFO、单实例轮转（`pumping` 闸门）、附件在
入队时取快照、停止与新会话清空队列并告知取消了几条。

## 顺带修的测试盲区

改这一处时发现两个面板单测里的假 DOM 有两处做虚了，而排队条是整条重画的
（`replaceChildren` 加逐条 `append`），这两处虚着会让新断言永远为真：

- `remove()` 是空操作。已移除的节点仍留在父节点的 `children` 里，
  「取消后队列为空」这类断言测不出东西。改为真的从父节点摘掉，`append` 记父节点。
- `className` 与 `classList` 各记一份。被测代码新建节点写 `className`、
  改状态用 `classList`，断言时就要猜某个类名是哪种方式加的。改为共用一个集合。

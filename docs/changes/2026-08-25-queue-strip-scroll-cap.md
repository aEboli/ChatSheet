# 2026-08-25：排队条限高三条并可滑动，取消即消失

排队条不再有几条画几条：高度封在三条，多出来的靠竖向滑动看，视口始终对着
下一个要发的那条。取消掉的排队输入直接消失，不再作为划掉的气泡落进对话流。

## 问题

**排队条会无限往上长。** 有几条排队项就画几条。实测在 320px 栏宽下，排到 6 条时
这一条占 123px、排到 12 条时占 249px，而对话区相应地从 715px 被压到 592px、466px。
被挤掉的正是用户正在读的回复，而排队条本该只是「还有什么在排」的索引。

**取消掉的输入仍占着对话流。** 取消后那条会以划掉的气泡落进对话流末尾，标注
「已取消，未发送」。当初这么做是想留住用户写过的字，代价是一条从未发生的输入被
永久记进「已经发生的事」里：取消几次就积几条既不能重发、也不进上下文的噪声。

## 改动

```text
┌─────────────────────────────┐
│  对话流（已经发生的事）      │
│  ...                        │
├─────────────────────────────┤
│           ⌐3 第三条…    × ▲ │  ← 最多三条，再多靠滑动
│           ⌐2 第二条…    × ║ │
│           ⌐1 下一个发这条 × ▼ │  ← 视口始终对着队首
│  状态          本轮 812 入 / 96 出 │
├─────────────────────────────┤
│  输入框                      │
└─────────────────────────────┘
```

**限高三条。** 上限由条目高度与间隙推出（`3 × 18px + 2 × 3px = 60px`），写成
CSS 变量：`--queue-chip-height` 同时是 `.queue-chip` 的 `min-height`，改尺寸不必
两处各算一遍。竖向可滑，横向仍然裁掉——横向溢出会顶出整页滚动条，`app.js` 的布局
自检把它算作缺陷。

**视口始终对着队首。** 每次重画后把 `scrollTop` 归到 0。

**取消即消失。** 取消一条、停止时清空队列，都只把它从队列里去掉并重画，不再往
对话流插气泡。停止仍然告知取消了几条——那是对「停止」这个动作的回执，一行系统提示。

代价说清楚：**取消掉的那段文字不再有地方可取。** 排队项上只有截断的一行，完整正文
在悬停说明里，取消后二者一并消失。按下取消时的意思本就是「这条不要了」；若之后确实
需要留一份，那是另一个改动（比如取消时把原文回填到空的输入框）。

## 两处实测推翻了预想

排队条的滚动与限高都是真实布局行为，假 DOM 的单测量不到。用 WebView2 同源的
Chromium（headless Edge）加载真实的 `index.html` 量过，其中两件事与我原先写的相反：

**一、`column-reverse` 的滚动范围是负的。** 我起初按「队首在最下面，归位就是滑到底」
写成 `scrollTop = scrollHeight`。实测读回来是 **0**：0 才是队首（第 1 位）那一端，
早排的那几条在负值处（6 条时下界 −63）。给 `scrollHeight` 能用，只是因为被夹到了 0，
属于碰对。现在直接给 0，并把坐标系写进注释。

**二、`replaceChildren` 不会清掉滚动位置。** 原注释写的是「整条重画会把滚动位置清掉，
所以要归位」，理由正好反了。实测滑到 −63 后重画，位置仍是 −63、露出的仍是第 4、5、6 位。
归位之所以必要，恰恰是因为位置会被保留：用户滑上去看过早排的几条，此后每次队列变化
都仍停在那里，而他要确认的永远是「下一个发哪条」。

**顺带删掉一条死规则。** 原本 `scrollbar-width: thin` 与 `::-webkit-scrollbar` 两条
都写着。实测滚动条占位宽度：都不写 15px、`thin` 10px、伪元素 6px、两条都写 10px——
两条都写时以 `thin` 为准，伪元素是死规则。宿主固定是 WebView2，因此只留伪元素，
既真到 6px 又能定滑块颜色。

## 实测数据

真实 `index.html`，headless Chromium，栏宽 320 / 360 / 420px 结果一致：

| 排队条数 | 排队条高（改动前 → 后） | 对话区高（前 → 后） | 可滑动 | 横向溢出 | 可见位次 |
| --- | --- | --- | --- | --- | --- |
| 1 | 18 → 18px | 697 → 697px | 否 | 无 | 1 |
| 3 | 60 → 60px | 655 → 655px | 否 | 无 | 1,2,3 |
| 6 | 123 → **60px** | 592 → **655px** | 是 | 无 | 1,2,3 |
| 12 | 249 → **60px** | 466 → **655px** | 是 | 无 | 1,2,3 |

滚动条占位只在真的溢出时出现（6 条起 6px），且是占位而非覆盖：取消按钮右沿 291
落在内容区右沿 296 之内，`elementFromPoint` 命中的就是按钮本身。

# 2026-08-26：点「适配」图标直接按当前对齐排版

点面板上的适配图标就按当前记住的对齐适配当前表，不必再在浮层里点一次
「居中 / 靠左 / 靠右」。浮层退到只负责换对齐方式。

## 问题

按钮上写着「适配」，点下去却什么也没排：只展开一张三选一的浮层，还得再点一项
才动手。

```text
点图标  →  浮层展开，表没动
点「居中」→  这才开始适配
```

两条后果：

**一、默认对齐形同不存在。** 代码里默认 `center`、浮层里也把居中高亮成当前项，
但这个默认值没有任何入口能直接用上——按默认排一次表照样要点两下。

**二、连续排版的成本翻倍。** 一份工作簿里挨着排好几张表是常见做法，对齐通常
一路不变。每张表都要重复「点开浮层 → 点同一项」，其中后一次点击不携带任何新信息。

## 改动

```text
点图标        →  按当前对齐（默认居中）直接适配
悬停图标      →  浮层展开，用来换对齐方式
浮层里选一项  →  记住这一种，并立刻按它适配
再点图标      →  沿用上次选的那一种
```

三处：

- `src/web/scripts/chat.js`：按钮的 click 从「开关浮层」改成 `runFit(fitAlignment)`，
  并在点击时收起浮层——动作已经发出，留着一张待选菜单会让人以为还要再选一次。
- 按钮的 `title` 与 `aria-label` 随当前对齐改写（`markActive` 里一并做）。
  图标是「向四角撑开」，看不出会按哪种水平对齐排版，而现在点一下就直接生效，
  事前能读到「当前是靠右」比事后撤销要省事。
- 方向键成为键盘换对齐的入口：在按钮上按 ↑ 或 ↓ 展开浮层，焦点落在当前项上。

### 为什么浮层留着悬停展开，而不是改成长按或右键

点击被主动作占用后，「换对齐」需要另一个入口。悬停本来就已经能展开，鼠标用户
不必学新操作；键盘用户原先靠点击展开，现在改用方向键——这也是 `aria-haspopup`
菜单按钮的常规键位，比长按、右键这类无提示的手势更容易猜到。

浮层向上弹出（控件在面板底部，向下会被裁掉），所以 ↑ 和 ↓ 都接受，不必先猜
它在按钮的哪一侧。

### 为什么在浮层里选一项仍然立刻适配

换对齐本身就是一次排版意图。选完还要再点一次按钮，等于把一件事拆成两步，
正是这次要修掉的毛病。

## 验证

```powershell
node tests\web\fit-entry.test.mjs
```

新增 `tests/web/fit-entry.test.mjs`，锁住六件事：点图标就发出适配请求且用当前对齐、
点完浮层是收起的、选过之后再点沿用那一种、方向键展开浮层但不适配、浮层开着时点
图标照样适配、按钮说明与无障碍名写出当前对齐。

假 DOM 的断言容易对着空节点全绿，所以这套断言反过来验过两次：把 click 改回
`setOpen(!isOpen())` 会失败 6 条，把对齐名写死成「居中」会失败 2 条。

# 2026-09-01：对话界面动效与顶栏图标点击反馈

顶栏右上角三个图标（对话、设置、主题切换）点击后有一段短促的回弹动画；
对话流的每个新节点淡入上浮进场；气泡圆角放大并收出方向角；
操作栏按钮按下时整体微缩。

## 顶栏图标：为什么要一段「点完之后」的动画

这三个按钮点了都不在原地给出结果——换页、换主题都发生在别处，图标自己
动一下是「点到了」唯一的就地回执。纯 `:active` 只在按住期间生效，给不了
「点完之后」那段，所以分成两截：

- 按下缩小交给 `:active`（`scale(0.85)`，随按随缩、抬手即止）；
- 回弹交给 `is-tapped` 类（`nav-tap`：0.85 → 1.12 → 1，0.26s），
  app.js 在 click 时挂上、`animationend` 摘掉。

回弹的起点与 `:active` 的缩小档相等（都取 0.85），松手的瞬间才不会跳一下。
这条等式由测试断言。

主题切换按钮另有一套（`theme-tap`，0.32s）：它点下去换的是图标本身
（月亮↔太阳由 CSS 按 `data-theme` 显隐），缩放回弹在换脸的瞬间读不出来。
改成新图标旋转淡入——显隐切换让新图标的动画从头播，正好承接「点了、换了」。
ID 选择器压过类规则，两套不打架。

### 连点要能重放

对已带 `is-tapped` 的元素再 `classList.add` 同名类不会重启动画。所以顺序
必须是「先摘、读一次布局（`void offsetWidth`）把移除落进渲染、再挂」。
少了中间那步，第二下点击没有任何反馈——这类缺陷不报错，只是不动。

## 对话流进场动画

所有进对话流的节点（气泡、工具卡片、提示条、轮次组）都走
`mountToTranscript`，进场动画加在这一个入口上：首挂时加 `is-entering`
（`transcript-enter`：淡入 + 上移 5px，0.18s），动画结束或被取消后摘掉。

四条边界，每一条都对应一个不会报错的错法：

- **只在首挂时放**（以 `dataset.seq` 在不在为判据）。重复挂载是 showPending
  把指示器移到末尾、或还原时按序号重排——内容早已在场，再淡入一次是闪烁。
- **重挂时必须主动把类摘掉。** 这一条是复核阶段在真实渲染器里量出来的：
  「只在首挂时加类」挡不住重播，因为类还在。`append` 一个已是子节点的元素
  等于「先摘再插」，移出文档会取消动画、插回去又重新起播。实测进度从 170ms
  退回 0ms，表现是那个气泡可见地闪两下。会撞上的都是毫秒级路径：showPending
  在下一个事件里把指示器移到末尾、`sealOpsBatch` 把「已完成」胶囊移到组后面。
- **`animationcancel` 与 `animationend` 都要听。** 动画被取消时只有前者会来
  （`sealOpsBatch` 把仍在动的卡片搬进未渲染的组容器就是这种情形），只听后者
  会让类永久残留，日后该节点被重插时再淡入一次。
- **核对 `event.target`。** 气泡里有自己会动的东西（处理中那圈点），子元素的
  结束事件冒泡上来不该提前把外层的进场动画掐掉。

只动 `opacity` 与 `transform`：二者不参与布局，挂载后紧跟的
`scrollTop = scrollHeight` 量到的高度与动画无关，滚动定位不受影响。

## 气泡圆角

主圆角从 `var(--radius)`（6px）放大到 10px——气泡是界面里唯一成片出现的
软性元素，6px 在 4/5 宽的色块上显得生硬；别处控件仍用 `--radius`。

贴边的下角收紧成 4px（用户右下、助手左下）：左右角色本靠 1/5 留白区分，
方向角在窄栏留白被压缩后仍读得出来。收下角不收上角：新消息从下方长出，
尖角朝下与生长方向一致。

## 操作栏按下反馈

`.icon-btn` / `.approval-icon` / `.context-ring` 按下时整体 `scale(0.92)`。
缩按钮而不是只缩图标：这排按钮带底色描边，光缩图标边框纹丝不动，反馈
读不出来。不加松手回弹：这排按钮点了在别处立即有结果（气泡上屏、圆环
变色、盾牌换形），不需要图标自己交代。`transform` 不参与布局，行不抖动。

## 减少动效

CSS 那边沿用全局 `prefers-reduced-motion` 的 `animation: none !important`。
但仅靠它不够，所以 JS 侧在加类之前先问一次（新增 `scripts/motion.js` 的
`prefersReducedMotion()`，两处共用）。

理由是复核阶段两个维度独立指出的同一件事：动画不起播时
`animationend`/`animationcancel` 都不会来，类会永久留在节点上。单看没有后果
（两个类都只带 `animation`），出事的是用户中途改 Windows 的「动画效果」开关——
WebView2 实时跟踪它，`reduce → no-preference` 的那一帧，所有残留节点的
`animation-name` 同时从 `none` 变成真实关键帧名，按规范全部立即起播。用户什么
都没做，整条对话流一起淡入一次、顶栏图标凭空回弹一下。不加类就没有这条路。

这个偏好每次现问、不缓存：它在会话中途会变，缓存住等于把首次读到的值当成
永久事实。

两个类仍然只许带 `animation`、不带静态样式。这条规矩现在的意义是：让「类残留」
永远等价于「什么都不显示」，而不是留下一个看得见的怪状态。

## 新增的验证通路：PaneHarness --motion

复核暴露的那个重播缺陷，此前三层检查（假 DOM、CSS 静态正则、`--theme` /
`--picker`）全都测不到——它是 DOM 规范的行为，代码里没有任何痕迹，表现只是
气泡闪两下。所以照 `--theme` / `--picker` 的形制加了第四个模式，用
`getAnimations()` 量「动画此刻在跑没跑、播到第几毫秒」。

一条走过的弯路值得记下：最初在注入脚本里**复刻**了一份挂载逻辑。修好
`chat.js` 之后断言照旧失败——红的是复刻件，而它已经不代表面板的行为了。
改成按宿主推送的格式投一条 `agent` 消息（`stage: retry` 只调 `showPending`），
让 bridge → `handleAgent` → 真实的 `mountToTranscript` 跑起来。测试要驱动
真实代码路径，复刻件只会与实现漂移。

同类的一个假绿也在这里踩到：`reset` 清了 DOM 却清不掉 `chat.js` 里的
`pendingBubble` 引用，之后的推送会走「气泡已存在」的重挂分支，那时压根没有
动画可取消，「取消后类摘掉了」这条断言轻松通过。改用工具卡片（每次推送都新建
一张，必然是全新首挂），并加了一条前置断言证明搬走那一刻动画确实还在跑。

`--motion` 也接进了 COM 自动化接口（`DriveMotionForTest`），于是
`scripts/verify-motion-host.ps1` 能在**真实 Excel 里用已安装的那份构建**验一遍
（24 条）。这条必须有：Excel 跑的是安装目录里的 DLL 与 web 文件，源码修好、
PaneHarness 全绿，都不等于装上的那份是新的——脚本第一步就核对安装目录。

### 一条竞态判据与一条确定性判据

「重挂没把动画倒回重播」这件事有两种量法，都留着，因为各有各的短板：

- **量进度**（首挂 → 等 90ms → 重挂，读 `currentTime`）。直观，但有竞态：
  动画只有 0.18s，等待加往返有时落到窗口外，那时读到「无」。所以只在真的量到
  在跑的动画时才断言，否则明说跳过——竞态的断言比没有更坏。进程内实测稳定在
  150-165ms，连跑三次都赶上了。
- **同一个 JS 任务内首挂再重挂**，读类还在不在。中间不出帧，`animationend` 绝无
  可能已触发，因此类的去留完全取决于代码有没有主动摘——与时序无关，两个版本
  必然给出不同结果。COM 那侧往返远超 0.18s，用的就是这一条。

回退修复后两条同时变红（进度 164ms → 0ms；同任务里类残留且动画重播 @0）。

另一处踩到的坑：同一个 JS 任务里**忙等推不动动画时钟**——
`document.timeline.currentTime` 在一个任务内是常量，试图用忙等制造「过了 80ms」
只会读到 0。想量进度就必须让渲染器出帧。

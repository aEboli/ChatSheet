# 2026-08-30：一键测试全部模型

列头加「测试」，点一次把整份目录逐个测过来，并发 5。能用的模型名变绿、
报错说没这个模型的变红。

## 与既有规格的冲突，以及怎么处理的

归档的规格里原本有一条明令禁止：**「不得对完整目录提供批量确认」**。那条不是随手写的，
理由写在旁边——目录有几十个 ID 就是几十次计费请求，而那正是用户想避开的开销。

本次按需求改写了它。改写不是删掉，而是把代价变成硬要求：

- 提供整目录确认，但它必须是与「只测名单」**分开的动作**；
- 控件必须在**用之前**说清这一次会发多少条请求；
- 并发是允许的（几十个模型串行等不起），但必须有界，且必须说清「并发会招限流，
  而限流记为未确认」——花了钱没拿到答案；
- 单个请求的确认**不得**因此变成并发的。

最后一条是分层设计的来处，见下。

## 并发怎么做的：整批占一次闸门，批内 N 路

`ModelProbe` 原有一道单飞闸门（`SemaphoreSlim(1,1)`），注释里写着「并发招限流」。
最省事的改法是把它放宽到 5，但那样**所有**探测都能并发——包括用户零散点的
「试一下」，那时同时有几个在飞谁也说不清。

改成分层：`ProbeManyAsync` 整批占一次闸门，批内用自己的信号量按 5 路跑。于是
「批跑期间零散探测排队等着」和「批内并发是确定的 5」两件事同时成立。

## 边跑边上色

后端每测完一个就推一次进度并带上该模型的判定，面板当场落到本地投影
（`recordVerdictLocally`）。几十个模型跑一遍要好一阵，只在整批结束时上色的话，
中途整列都是「未确认」，看起来像卡住。权威值仍由整批结束时的回复覆盖。

## 顺带修的两个缺陷

### 「测试」和「确认」点不动

两个按钮的禁用状态按目录/名单里有多少模型算，而 `loadModels` 拉完目录后
**只重画了列表、没重画列头**。于是模型都出来了，按钮还停在「目录为空」那一刻算出的
禁用态，永远点不动。补一行 `renderColumnHead()`。

测试为什么没抓到：`model-test-all.test.mjs` 原先都是先塞好目录再 `syncPicker`，
走的是「同步就有目录」那条路；而真实使用是「浮层先开、目录后到」。整个 `loadModels`
的异步到达路径此前**一条断言都没有**，一并补上 5 条。

### 档位列的标题与档位名差 7px

标题在**整列**里居中，而档位行在**列表的内容框**里居中，两者相差正好一条滚动条的
宽度。先试过「档位列表不预留滚动条槽位」，宽面板上对上了，矮面板下又错开——那里
档位列真的会滚，真实滚动条同样吃掉 15px。

真正的原因是「两个盒子的可用宽度不一致」。改法：滚动条收窄到 6px（照
`.queue-strip` 已记下的实测结论：只有 webkit 伪元素能真收到 6px），列头补一条
等宽的右内边距。算一遍就对得上——列头可用宽 `W-6-12`、列表可用宽 `W-3-3-6`，
两者中心都在 `W/2-3`。七种尺寸下相差全部归零，含会滚动的矮面板。

## 测试打的是真实实现

`BulkTestTests` 一开始写的是「复刻 `ProbeManyAsync` 的调度形状」——那只能证明抄来的
那份对，改了真实实现照样全绿。现已改成起一个**进程内的并发 HTTP 服务**，
按模型名分流应答，跑真实的 `ProbeManyAsync`。

服务必须并发处理连接：`RetryResetTests` 里那个 `ScriptedServer` 是刻意串行的
（它被验的客户端一次只发一个请求），直接拿来用会把并发度压成 1，那时无论实现对不对
峰值都是 1，断言永远是绿的。

判「有没有排队」用的是**区间是否重叠**，不是全局峰值。峰值会被一个竞态骗到：
服务端在写完响应之后才减在飞计数，而客户端此刻已认为请求结束，于是排在后面的探测
会与「正在收尾」的连接重叠，峰值虚高一格。

变异验证（都是改真实实现）：

| 变异 | 转红的断言 |
| --- | --- |
| 批内并发写死为 1 | 并发达到 5（实测峰值 1） |
| 整批不占闸门 | 闸门被占着（剩余许可 1）、零散探测重叠 6 个、它在批跑结束后才开始 |

## 排查时踩的一个坑

改回正确实现后测试仍然报红，我据此判断「实现有真缺陷」并往下查了几轮。真相是
**读到的是没重新构建的旧产物**——那一版还带着「去掉闸门」的变异。用日志把闸门的
取/放时刻打出来才看清：批在 `11.829` 放开闸门，零散探测在 `11.829` 拿到，
顺序完全正确。

这与仓库里已经记着的那条同源：面板缺陷先查装的是哪个构建。这次是同一个陷阱换了个
位置——不是「装的是旧 DLL」，而是「读的是旧输出」。

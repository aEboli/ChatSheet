# ChatSheet v0.10.0

模型列头的**「测试」点下去先问测到什么程度为止**：找到 1 个能用的就停、找到 2 个能用的就停、全部测试。选中一档才发请求。

此前点它就把整份目录扫完——一个模型一条计费请求，网关动辄返回几十个 ID，于是一次点击就是几十条请求、要等好一阵。而多数时候想知道的只是「有没有一两个能用的」。

## 三档范围，每档说清代价

菜单在列头下方展开，三档都写出了两个数字：

- **上界一律是目录条数**（几十个模型就是几十条）。带目标那两档也一样——目录里能用的不足目标数时会全部测完。把上界写成目标数是不诚实的，那会让你按 2 条去估几十条的账。
- **下界是三档真正不同的地方。** 并发是 5，达标那一刻已经发出去的收不回来，所以「找 1 个就停」最少也是 5 条，不是 1 条。省下的量级是 40 → 5～6。

只有「能用」算达标。被限流的记为「未确认」——那是花了钱没拿到答案，不算找到了一个能用的，运行会继续。

## 达标只停止派发，不取消

已经发出去的请求（最多 4 条）照常跑完并记下判定。钱已经付了，取消它们既拿不回钱也拿不到答案，那几行还会停在灰色再也不更新。

## 三种结局分得开

跑动中按钮显示「停止 1/2 可用」——分母是目标数。用目录条数当分母的话，一次「找 1 个就停」会显示「停止 3/40」，读起来是「还要跑 37 个」，而它随后就停了，看起来像断了。

跑完之后列表上方留一句，三种情形各有各的说法：

- 达标：找到几个、发了几条、剩下几个没测；
- 你按了停止：发了几条，已测出的都保留着；
- 整份目录都测完了。目标没达成时会明说「只找到 1 个能用的（想找 2 个）」——那时你选的是省钱的档、付的是全款，不说出来界面上看不出这件事。

## 顺带修的两处

**对话进行中点「测试」此前没有任何反应。** 加载项在对话进行中会拒绝测试，而那条拒绝只写进日志。现在按钮先禁掉并在悬停里说明原因。

**停止之后进度会凭空复活。** 中止批量时有几个探测仍在飞，它们迟到的回报会把已经收尾的进度重新置上，列头按钮回到「停止 n/总」——而后端已经没有批量在跑，再点它没有任何效果，关面板也不清。

## 升级须知

无需改配置，设置、密钥、常用名单与面板宽度都保持原样。覆盖安装前请完全退出 Excel。

打开后在模型选择器里点一下「测试」：应该出现三档，而不是直接开跑。

## 验证

- **`BulkTestTests` 新增四组**：达标后实发恰好等于并发数、已派发的都拿到判定、闸门到整批结束才放开、限流不算达标（跑到底）、目标达不到时跑满全程且不谎报、目标为 0 与负数都全量。判据是**服务端服务了几个连接**——回调次数说明不了有没有省钱，而省钱是这个功能的全部理由。
- **`model-test-all.test.mjs` 60 → 81 条**：原先「点一下就发请求」那一整段改写成「开菜单、选一档」，新增三档的上界/下界/提前结束条件、分母是目标数、三种结局各自的说法、迟到推送不复活、对话在飞时禁用并说明。
- **`PaneHarness --picker`**：菜单三档都在浮层裁剪框内、各有真实高度、至少露两档、装不下时可滚、展开后列表仍有可用高度、列头仍不溢出、两套主题各用自己的背景色。跑了 300×560、360×340、420×760、480×760 四种尺寸。
- **变异九次**（C# 三次、面板四次、CSS 两次）。其中三次初次不红，暴露出断言太松、时序太齐、以及读到了输出目录里的旧副本，都已修正。
- **全套**：ToolTests 717、网页 964、`--picker` / `--motion` / `--shake` / `--theme` 全绿，`dotnet build -c Release` 0 警告 0 错误。

## 未验证

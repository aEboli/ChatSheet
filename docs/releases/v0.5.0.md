# ChatSheet v0.5.0

`v0.5.0` 回答一个此前只能靠试错回答的问题：**网关返回的这几十个模型 ID，哪几个真能用？**

选择器现在会标出用过的模型能不能用，把常用的排到最前面，还能对着没用过的点一次「试一下」就知道结论。版本号从 `0.4.0` 走到 `0.5.0`，是因为这是一项此前不存在的能力，而不只是修正既有行为。

## 问题

模型选择器把 `GET /models` 返回的 ID 原样列出来。网关动辄返回几十上百个，其中能用的往往只有两三个：有的没有配额，有的账号无权限，有的只是别名，有的一发就 404。要确认哪个能用，唯一的办法是选中它、发一句话、看报什么错——错了再换下一个。

问题的根子在于协议本身不提供答案：没有任何协议提供「该模型支持什么」的查询接口，`GET /models` 只给名字。

## 新增：用过的模型自动带上结论

判定从**已经付过钱的那一轮对话**里来，不额外发任何请求：

- **能用**：本轮收到过任何流式事件。到达了模型就是可用性的全部主张，之后无论出什么错都不改这个结论。
- **报错说没这个模型**：本轮失败，且服务端原文点名了这个模型。
- **未确认**：其余一切。密钥被拒、限流、5xx、超时、网络故障、我方请求有问题，说的都是账号或网络，与模型无关。

「能用」刻意不包含「支持工具调用」：加载项已经为不支持工具的模型准备了文本指令协议与顾问模式，把它算成不可用会把一个规范认定可用的选项从眼前拿掉。

### 判「不可用」要求服务端点名模型

这是整套判据里最要紧的一条。地址填错导致的裸 404、密钥被拒的 401/403、限流的 429、网关抖动的 5xx 一律算「未确认」——否则一次限流就会给你天天在用的模型判死刑。

实现上有个不显眼但决定成败的细节：判据只读服务端原文，**绝不读加载项拼装过的错误消息**。加载项会给 404 追加一句「请检查接口地址与模型名是否正确」，那句话里含「模型名」二字。读它会让每一个 404 都变成假阳性，包括与模型完全无关的地址错误。为此接入层新增了一个只装服务端原文的字段。

## 新增：常用名单与一个筛选开关

- 点行末的星把模型加进常用名单，**名单里的排到最前面**。无条件生效，不需要开关。
- 列头的「只看名单」把列表收窄到名单内，默认关。老用户升级后选择器逐字不变。
- 名单按连接记住并落盘；判定记在内存里，重启 Excel 后清空——网关随时可能补上配额，落盘的判定要用户自己去清理才能翻案。

开关不会把人锁在外面，三条兜底：

- 名单为空、或名单里的模型当前网关一个都不提供时，一律显示完整目录。后一种覆盖的是「换过网关」「模型下架」「几个月前打错的 ID」——名单非空但全部失效，收窄后会只剩当前模型，而能用的全被藏起来。
- 当前选中的模型永远可见，无论在不在名单里。
- 刚标第一颗星时不当场收起其余的。那一下说的是「记住这个」，不是「藏起另外几十个」。

**标注永不隐藏模型**，收起只由你的开关决定。所以误判的代价上限是标错一次、重试即改，而不是一个好模型被永久藏起来。

## 新增：对没用过的模型点一次「试一下」

没有判定的行末有个「试一下」，点一次发一条最小请求，秒级出结论。列头的「全部确认」把名单里的逐个确认完，带进度、可中断、已得结果保留。只对名单提供批量，不对完整目录——几十个 ID 就是几十次付费请求，而那正是要避开的开销。

状态点四态：实心绿=能用，实心红=报错说没这个模型，空心=未确认，琥珀描边=正在确认。

### 确认请求是真实请求的真子集

只准去掉字段，不准换值：不带工具、不带图片、**整段不传思考参数**、输出上限压到最小。

这一条不是洁癖。换了值就有两种误判，其中一种主动骗人：

- 真实对话默认走 High。会拒绝 `high` 的模型，如果确认时发的是另一个值而它接受，确认就给绿灯，而真实对话每次都失败。
- 反过来，只认 `low/medium/high` 的网关会拒绝「关闭」这个值，于是这些模型**永久**确认不出来，点多少次都一样。

为此本次修了三个先前没暴露出来的缺陷：

| 缺陷 | 影响 |
| --- | --- |
| 「关闭思考」发的是一个关闭值，不是不传 | 上面那两种误判 |
| Chat Completions 只发 `max_tokens` | OpenAI 推理模型对它直接回 400。现在按服务端的拒绝换用 `max_completion_tokens` 并记档，**真实对话一并受益**——这个 400 在真实对话里同样会挡住 |
| OpenAI Chat Completions 的流式解析器没有错误分支 | 它是默认协议，却唯一认不出「200 开流、错误在体内」。此前那种响应表现为「正常返回但一个字都没有」 |

确认请求还固定带一条极短的用户消息：Anthropic 与 Gemini 会把系统提示抽到顶层字段，一个「只带系统提示」的请求在那两个协议上会产出空消息列表并被拒绝。

### 确认不会打扰你正在做的事

- 同一时间只确认一个，其余排队。并发招限流，而限流的结论是「未确认」——等于花了钱没拿到答案。
- **对话在飞时不许确认**，会明确告诉你原因。几条请求压在一个账号上可能把你那一轮带着完整上下文的请求给限掉。
- 确认有 15 秒截止时间，且不走重试退避（完整退避是 23 秒，与「点一下就知道」矛盾）。重试留给你再点一次。
- 批量的「停止」与对话的「停止」是两个独立动作，互不影响。

## 升级说明

从 `v0.4.0` 升级不需要任何手工步骤，判定与名单都是新增的：

- 开关默认关，名单初始为空，所以升级后选择器的唯一变化是**用过的模型会开始带上标注**。
- 判定不落盘，升级后第一轮对话就会重新建立。
- 名单存在 `%LOCALAPPDATA%\ChatSheet\favorite-models.json`，与设置文件分开——设置文件由多个写入方整体重建，放进去会被无关的保存抹掉。

## 已知限制

- **从没发过一轮、也没点过「试一下」的模型显示「未确认」**。这不代表它不能用，只代表还没有证据。
- 判定是启发式的，因为没有任何协议提供查询接口。所以它只加标注、从不隐藏——误判的代价上限是标错一次。
- 判定按「连接 + 模型」记在内存里，重启 Excel 后清空；换连接或为同一地址换密钥时也会作废该连接的判定（一个账号能碰到哪些模型跟着密钥走）。
- 本机 CLI 模式下密钥在 CLI 自己的配置里、不经加载项的加密存储，因此换那种密钥不会触发作废。

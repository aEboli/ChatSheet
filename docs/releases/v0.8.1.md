# ChatSheet v0.8.1

批量探测模型时，**探完一个那一行就当场变绿或变红**，而**正在探的那几行都有扫光**。

这是个补丁版。`v0.7.0` 做过一遍「点了之后有没有反应」，`v0.7.1` 给批量测试补上扫光，
但批量探测这件事本身还剩两个缺口：名单批量确认从来没有边跑边上色，而扫光落错了行。

## 名单批量确认从来没有边跑边上色

列头「确认」跑的是名单里的模型，一个一个来。此前它每个模型只推一条进度，而且推在
**探测之前**——那条消息里没有判定，因为判定还没出来。探完之后什么都不推。

于是整批跑完之前，一行都不会变色。颜色要等整批结束时由回复一次性补上，而名单十几个
模型就是十几次往返。中途整列都是「未确认」，看起来就是点了没反应。

列头另一个按钮「测试」（跑整份目录）一直是每探完一个就带着判定推一次的。所以这不是
设计取舍，是这条路漏了。现在补齐：探完就推，服务端点名说没这个模型的那种失败也算
一条判定，照样推。

## 扫光此前永远落在一行已经上了色的行上

「测试」并发 5，同一时刻在飞的是五个模型。而面板只用一个字段记「正在测哪一个」，
那个字段只能由推送来填，推送又只在探完之后发——所以它装的永远是**刚探完**的那一个。

结果是扫光落在一行刚刚变绿或变红的行上：已经有结论了却还挂着「正在测」的高光，
而真正在飞的五个一个都没标。两个互相矛盾的标记压在同一行，读不出这一行到底测完了没有。

现在探测层多了一个「开始探」的回调，在模型真的拿到并发槽位之后才响——不能提前到入队时，
排在后面等槽位的还没开始发请求，提前标上等于说假话。面板据此把「正在探」从一个字段
改成一个集合，并发 5 就是 5 行同时扫。

用户中途点停止时，已经在飞的那几个不会再收到「探完」的消息，因此清空进度时把集合一并
清掉——否则批量早停了，列表里还有几行一直扫下去。

## 限流不再把测出来的结论抹成灰

这一条没在报告里，是修上面两条时发现的两侧不一致。

加载项侧记判定时遇「未确认」直接跳过——限流一类是花了钱没拿到答案，不是证据，不该抹掉
上一次的结论。面板侧却照写。后果看得见：上次测出能用的模型这次被限流，行上的绿当场消失，
而整批结束时权威快照仍说「能用」，绿又回来。

一行在批量途中掉了色又找回来，比从头到尾不变色更难读。面板侧现在与加载项侧同一条规则。

## 颜色规则一行没改

`v0.6.0` 起「能用」显绿、「不可用」显红的规则、两套主题各自的调色板变量，都已经在位。
这一版缺的从来不是颜色，是把行送进那两条规则的那一步。所以升级后看到的绿和红，与
逐个点「试一下」时看到的是同一对颜色。

## 升级须知

无需改配置，设置、密钥、常用名单与面板宽度都保持原样。覆盖安装前请完全退出 Excel。

## 验证

- **面板单测 810 条**（新增 `model-probe.test.mjs` 的「批量确认边跑边上色」一节、
  `model-test-all.test.mjs` 的「并发在飞的那几行都被标出来」一节、`model-favorites.test.mjs`
  锁住「未确认」不覆盖已有判定）。
- **变异验证**：五处修复各故意改坏一次，分别红 3 / 1 / 2 / 4 / 1 条。第一版的批量确认
  测试是假绿——复用了前一节已经探出结论的模型，删掉修复照样通过；改成在一个从未确认过
  任何模型的连接上跑。
- **`ChatSheet.ToolTests` 702 条**：新增一条起真实 HTTP 服务跑真实批量探测的用例，
  盯住「同时在飞的峰值等于并发数而不是模型总数」。`onStart` 提前回调不报错、不变慢，
  只会把标记变成噪音，只有这条拦得住。
- **`PaneHarness --picker` 76 条**（真实 WebView2，走真实推送路径，读 `getComputedStyle`
  的实际值）：判不可用的名字与状态点都是 `rgb(242, 139, 130)`、判未确认是
  `rgb(230, 232, 234)` 且行上没有结论 class、红之后再推「未确认」红不退、两行同时在飞
  各挂一个运行中的 `::after` 动画、探完的那行收掉而另一行仍在扫、批量结束后全收掉。
- `--motion` / `--theme` 全绿。装好后安装目录下的 web 资产与源码逐字节相同。

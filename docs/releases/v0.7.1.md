# ChatSheet v0.7.1

批量测试模型时，**正在测的那一行有一道高光从左扫到右**。

这是个补丁版：`v0.7.0` 把「点了之后有没有反应」做了一遍，但漏掉了批量测试自己——
一次跑几十个模型、要好一阵，而列表里唯一的进度线索是列头按钮上的「停止 3/40」那个
数字。看得出跑到第几个，看不出正在测哪一个。

## 「正在测」此前压根没有标记

不只是没有动画——那一行在界面上与还没测的行完全一样。

`is-probing` 只在用户逐个点「试一下」时置上。批量测试整批只占一次单飞闸门、不逐个
置 `probing`（那是 `v0.6.0` 分层设计的一部分：批内并发 5，零散确认排队等着），所以
批量期间没有任何一行会是 `is-probing`。当前测到哪一个只存在于内部的批量进度里，
没有任何地方把它画出来。已测完的行会变绿变红，正在测的那一行没有任何标记。

因此这一版不只是加了个动画，是把这个状态第一次画出来。

## 为什么是扫光而不是闪烁

闪烁是明暗交替，会和「未确认」那个闪动的状态点撞在一起：一行里两处各按自己的节奏
闪，读起来像画坏了。扫光有明确的方向，而方向本身就对应「从左往右过一遍」这件事。

高光取中性色，不用绿也不用琥珀：这一列的颜色已经被判定占满了——绿是能用、红是不能
用、琥珀是那个状态点。再给进度一种颜色，用户要多记一条。两套主题各有一份（浅色下
压暗、深色下提亮，方向相反但语义一致，都是与底面分开的一道高光）。

周期 1.1 秒：批量并发 5，单个模型通常一两秒内有结果。再快显得慌，再慢则一个模型
测完了光还没扫过一遍，看不出它在动。

## 减少动效

开启系统的「减少动效」后，那一行改为一道静止的均匀高光——不动，但仍然指得出来。

不这么处理的话，动画一关那一层会以一道居中的软光带静止在行上：看得见，却读不出
「这一行被标记了」，而它是批量期间「正在测哪一个」的唯一提示。

## 升级须知

无需改配置，设置、密钥、常用名单与面板宽度都保持原样。覆盖安装前请完全退出 Excel。

## 验证

- **静态断言增至 87 条**（`tests/web/chat-motion.test.mjs`）：循环（与本项目其他动画
  相反，扫光必须循环——只放一次的话光扫过去就没了而那一行还在测）、周期在 0.6–2s、
  只动 `transform`、从左到右、两端各移出整行宽度、渐变两端透明、高光走调色板变量且
  两套各定义一份、不吃点击、定位与裁剪只加在标记类上、减少动效有静态兜底、标记取自
  批量进度而不是 `isProbing`、模型 ID 折叠大小写。变异八次确认全部会红。
- **`PaneHarness --picker` 新增 12 条实测**（真实 WebView2，走真实的进度推送路径，
  不复刻渲染）：没在测的行没有扫光、被标记的行动画真的在跑且挂在 `::after` 上、
  处于运行态、那一层是渐变、行被裁剪、不吃点击、同一时刻只有一行在扫、批量结束后
  收掉、另一套主题下同样在跑且用的是那一套自己的高光色。
- **真实 Excel**：装好后用已安装的那份复验 10 条。
- 全套回归：网页 729 条、`ChatSheet.ToolTests` 569 条、`--motion` / `--shake` /
  `--theme` / `--picker`（含 320×560 窄栏）全绿。

### 顺带修掉一个既存的飘测

`--shake` 的「产品按钮」那一组约每三次跑会红一次，与本版改动无关：那一组要求浮层
开着而模型列表还没到（列表一到那个按钮就不再禁用），列表在量坐标与点击之间到达时
浮层内容位移，同一坐标换成了别的元素——实测点到过隔壁模型行上的「试一下」。现在先
看这一下究竟点在了谁身上，不是目标就明说跳过，不报「没抖」。连跑五次稳定。

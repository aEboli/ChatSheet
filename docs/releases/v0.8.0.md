# ChatSheet v0.8.0

点「允许」之前，**你能看见要改成什么**。

`v0.5.0` 到 `v0.7.1` 四个版本都在回答元层的问题：哪个模型能用、点了有没有反应。表格能力面自 `v0.2` 的合并单元格之后没有动过。这一版回到干活那一层：默认的逐项审批此前只告诉你「改哪、改多少格」，不告诉「改成什么」——而加载项为了估算范围，已经把当前值读出来过一次，读完就扔了。

版本号走到 `0.8.0` 是因为新增了此前不存在的能力（前后对照、跳转、有范围的授权），并修掉四个会让撤销变成二次破坏的缺陷。

## 审批卡看得见内容

```text
需要确认：写入值
影响范围：Sheet1 的 2-4 行 × B-C 列，共 6 个单元格    ← 可点，跳到那片格子
┌──────────────┬────────────┬────────────┐
│ 位置         │ 现在       │ 将改为     │
├──────────────┼────────────┼────────────┤
│ 第 1 行 第 1 列 │ 2025-08-31 │ 2025-09-01 │
│ 第 1 行 第 2 列 │ （空）     │ 0          │
└──────────────┴────────────┴────────────┘
另有 19 个单元格未列出。
[允许] [本轮同类允许] [含结构允许] [拒绝]
```

用的是估算影响那一次已经读到的值，不额外多读一遍——审批发生在 UI 线程上，为预览多跑一次 COM 会让大范围下的 Excel 假死，而那时卡片还没画出来。

几条边界都是实测定下来的：

- **日期不再显示成序列号。** `Value2` 把日期给成 `45900`、时间给成 `0.75`、百分比给成 `0.1234`。摆在「将改为 2025-08-31」旁边，看起来像换了一种东西而不是改了一个值。改用 `Range.Text`，四种格式一次全对。列宽不足显示成 `####` 时退回底层值。
- **`Range.Text` 对多格范围不返回二维数组**（与 `Value2` 不同），所以必须逐格读。对照最多只画 8 行 × 6 列，读窗口之外的格子没有用处，48 次 COM 调用只发生在审批路径上。
- **空与「读不到」分开。** 原值是空、新值是 0 是一次正常写入；范围过大读不到当前值是探测失败。合成一个样子会让人把后者看成前者。
- **公式给 120 字，普通值 40 字。** `=IFERROR(VLOOKUP($A2,Sheet2!$A:$D,4,FALSE),"未找到")` 是 51 个字符，截到 40 恰好切掉关键部分——而公式错了要跑一遍才知道。
- **抹除类另有一栏。** 合并是唯一会静默丢值的写操作，卡上会写明「合并会丢弃 N 个有内容的单元格，只保留左上角那一个」，N 是范围内的总数而不是卡上列出的几格。

## 范围可以点进 Excel

审批卡、操作卡的成功摘要、轮次组里凡是已经译成「行号 × 列字母」的位置，都是跳转入口。核对不必再自己去表里翻。

会改变当前选区，悬停说明写了这一点。刻意不做「高亮完还原选区」：Office 对象每次读取都是新代理，不能用 COM 标识判断是不是同一个范围，误还原是静默出错。

## 撤销不再说谎

四处，全部实测复现过：

| 情形 | 此前 | 现在 |
| --- | --- | --- |
| 建图后点撤销 | 恒报「找不到图表「」」 | 回报 `Shape.Name`，真能删掉；取不到名字就不给按钮 |
| 建图撤销之后 | 按钮变「恢复」，再点必然失败 | 撤掉按钮并说明图表无法自动重建 |
| 均匀无填充的范围 | 撤销后变成**实心白底**，网格线消失 | 仍然无填充 |
| 混合填充 / 双色填充 | 撤销后整片**变黑底** | 各自保留原色 |

后两条是同一个根子：**宿主用一个具体值表示「这一项不统一」。**

```text
                  Pattern   Color      ColorIndex
颜色不同           1        0          DBNull
一格黑一格红       1        0          DBNull
整片真黑           1        0          1
均匀无填充         -4142    16777215   -4142
```

`Interior.Color` 在「颜色不同」和「整片真黑」两种情形下读数**逐字相同**，所以它自己不能当判据；`Pattern` 在颜色不同时是统一的 `1`，也拦不住。诚实的那一项是 `ColorIndex`。而均匀无填充时三项全是真实值，任何「缺失才跳过」的判据都会放行，写回 `Color` 会把 `Pattern` 从 xlNone 顶成实心——这是最常见的范围形态（任何没上底色的表）。

字体那边同构但判据不同：跟随主题的字色读 `Color=0`、`ColorIndex=1`、**`ThemeColor=2`**，显式黑色前两项完全一样、`ThemeColor` 为空。只写回 `Color` 会把主题联动打掉，撤销之后文字不再跟随主题——换主题或深色模式下才看得出来。所以跟随主题的写回 `ThemeColor` 与 `TintAndShade`，显式颜色的写回 `Color`。

另外三件：

- **字体名、下划线、删除线补进快照。** 三项单值读取，此前完全不在快照里，清除格式会把它们一并重置。
- **边框如实披露。** 一片范围有四条外边、两条内线加两条对角线，逐边读的 COM 成本远高于其余九项之和，所以不采。但清除格式会抹掉边框，卡片会写明「撤销能找回内容与字体、填充、对齐这些，但边框不会回来」。
- **不给撤销按钮时一定说原因。** 缺按钮本身是可见的，缺原因会被当成故障——而它其实是「保不住足以完整还原的依据就不承诺撤销」这一有意为之的取舍。

## 重叠的撤销先给警告

两条写入范围相交时，撤较早那次会盖掉较晚那次。乱序撤销本身是刻意保留的能力（改 A 列与改 F 列不相干），要拦的只是**静默覆盖**：第一次点击不执行，报出会覆盖哪一次，按钮改成「仍然撤销」，再点一次才执行。

相交只按工作表名加 A1 行列区间判断，不拿 COM 代理去比。多区域并集地址（`B:B,D:D`）算不出区间时按不相交处理，退回今天的行为，而不是拿一个猜出来的区间去拦人。

## 「每轮确认」不再等于逐项审批

设置页一直摆着这一档，执行器从未实现——选它与逐项审批走同一条路径。现在授权是「工作表 + 风险类」：

| 类 | 工具 |
| --- | --- |
| 格式 | `format_range`、`set_number_format`、`autofit_range`、`fit_range` |
| 写入 | `write_values`、`write_formulas` |
| 抹除 | `clear_range`、`merge_cells`、`unmerge_cells`、`sort_range` |
| 结构 | `add_worksheet`、`rename_worksheet`、`create_table`、`create_chart` |

四类而不是三类：抹除与写入必须分开。写入覆盖的值快照能还原，清除会抹掉内容与格式，合并会静默丢值，排序会整行搬动。批准「往这几格写个值」不该顺带放行「清空整张表」。

**结构永远不被其他授权捎带放行。** 「本轮全部允许」改成「本轮同类允许」，要放行结构必须点写明「含结构允许」的那个按钮。当前授权显示为盾牌旁的文字芯片（`Sheet1 · 格式`），**点它可以收回**。授权只活本轮、只活在内存里。

轮进行中切换策略，下一刀写操作就按新策略走。

实测对照（mock 场景连发三次不同的格式工具，再来一次 `add_worksheet`）：

```text
PerWrite  点 4 次   问过：format_range、set_number_format、fit_range、add_worksheet
PerTurn   点 2 次   问过：format_range、add_worksheet
```

## 顺带修的两个

**处理方式跨重启不生效。** `approval` 只写进 `settings.json`、从来没被读回来，每次重开 Excel 都静默回到逐项审批。界面显示的是内存里的值，行为按文件走，只有重启后才对不上——所以一直没被发现。

**系统提示注入本机当前时间。** 模型没有时钟，「日期写今天」会得到一个训练数据截止前后的日期：形态合法、不报错、也没有任何工具返回值来纠正它。实测 2026-09-04 当天写出 `2026-01-19`。现在每轮刷新系统提示时写入当前时间与时区，三种工具形态共用。

## 影响面说清楚

- **自动调整与适配**按整列整行生效，不限于所选那几格。审批卡不再用单元格数表示影响面，改为写明作用范围。
- **新建工作表会成为当前活动表**，之后未指定工作表的操作都会落到它上面——卡片上写出来了。
- **建表会把首行当作标题**（默认如此），撤销会去掉表格但样式留在格子上。

## 升级

覆盖安装即可，设置与密钥保留。安装前请完全退出 Excel。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1 -Action install
```

处理方式此前从未被读回过，升级后第一次打开会按 `settings.json` 里存的那一档生效——如果你以前选过「全自动」但重启后一直是逐项审批，这一版会真的变成全自动。请确认一次。
